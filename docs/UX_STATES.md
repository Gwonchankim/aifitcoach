## 1. 공통 규칙

### 1.1 상태 5종 정의

| 상태 | 정의(판별 기준) |
|---|---|
| **빈(empty)** | 요청은 성공했으나 보여줄 데이터가 0건이다. 또는 선행 데이터(프로그램)가 없다. |

### 1.3 마이크로카피 톤

- **존댓말 + 간결체**(`~해요`, `~해 주세요`). 최대 2문장. 1문장 = 원인, 1문장 = 다음 행동.
- 버튼은 **동사 중심 2~5자**: `다시 시도`, `루틴 보기`, `운동 종료`, `휴식 종료`, `계획 만들기`.
- **금지어**: 에러, 실패, 오류 코드, 서버, API, 동기화(내부 용어), 세션(내부 용어 → "오늘 운동"), 필드명(`sets`, `pain_areas` 등), 영문 상태코드, 스택/예외 메시지.
- **숫자·단위**: `62.5kg`, `9회`, `40초`, `1분 30초`. 무게는 소수점 1자리까지, 정수면 소수점 생략(`60kg`).
- **의료 표현 금지**: 진단·치료·완치·호전 등의 단정 금지. 통증 관련 문구에는 항상 "일반적인 안내이며 의료적 조언이 아니에요"를 함께 둔다(`docs/SAFETY_PAIN_MAPPING.md` 규칙 6).
- **과장 금지**: "완벽한", "최적의", "AI가 분석한" 같은 수식 대신 근거를 그대로 말한다(예: "지난번 3세트 모두 목표 상단을 채웠어요").

#### 2.1.1 스텝 버튼 배치 (F0-0, 확정 2026-08-05)

> 문제: 3/7(주당 일수)·4/7(1회 시간)은 칩 한 줄이라 콘텐츠가 화면 상단 1/4에서 끝나는데 버튼이 화면 최하단에 고정되면
> **가운데가 통째로 비고**, 7번 연속 누르는 화면이라 그 마찰이 누적된다.

**규칙: "짧으면 따라 올라오고, 길면 고정"** — 버튼 블록의 위치는 아래 한 줄로 정의된다.

```
버튼 블록 상단 y = max( 콘텐츠 마지막 요소의 아래 + 24px , 뷰포트 높이 × 0.65 )
콘텐츠가 뷰포트를 넘으면 → sticky(하단 고정)
```

| 스텝 유형 | 판별 | 버튼 위치 | 배경·경계 |
|---|---|---|---|
| **스크롤 없음**(대표: 3/7 주당 일수, 4/7 시간) | 문서 높이 ≤ 뷰포트 높이 | 콘텐츠 흐름 안. 콘텐츠 아래 24px, 단 **뷰포트 65% 지점보다 위로는 올라가지 않는다**(엄지 반경 §8 유지). 버튼 아래 남는 공간은 그대로 빈 여백으로 둔다 | 배경 불투명 불필요, **상단 경계선 없음** |
| **스크롤 있음**(대표: 1/7 프로필, 2/7 목표, 5/7 경력, 7/7 통증 — 기기·글자 크기에 따라 달라지므로 스텝 번호로 하드코딩하지 않는다) | 문서 높이 > 뷰포트 높이 | `position: sticky; bottom: 0`으로 뷰포트 하단에 고정. 스크롤 콘텐츠 하단에 **버튼 블록 높이 + 24px**만큼 여유를 둬 마지막 요소가 가려지지 않게 한다 | 배경 **불투명**(뒤 콘텐츠 비침 금지) + **상단 경계선 1px** |

### 2.2 S2 프로그램 확인 (F0 후속)

`POST /programs/generate` 201 응답 또는 `GET /programs/current` 200을 렌더한다.

**'왜 이 루틴' 근거 문구는 응답 필드로 조립한다** `[해석]` — `Program`에는 자유 텍스트 근거 필드가 없다(`goal`, `split_type`, `rules_version`, `excluded_exercises`, `sessions`만). 없는 필드를 요구하는 대신 클라이언트 템플릿으로 만든다:

- 목표 라벨: `diet`→다이어트 / `hypertrophy`→근비대 / `strength`→스트렝스

| 이미 오늘 세션 있음 | 409 | 즉석 생성을 **재시도하지 않고** 대시보드를 재조회해 `today.session_id`로 이동한다(F8-1). `session_id`가 여전히 null이면 이동하지 않고 §3.1 기본 409 문구만 남긴다 | "오늘 만들어 둔 운동이 있어요. 그 루틴으로 갈게요." |
| 에러 | 400/500 | 시트 유지 + 인라인 배너. 부위 버튼은 다시 눌린다 | §3.1 기본 문구 |
| 오프라인 | — | [그래도 운동하기] 비활성 + 사유. 새 즉석 세션 생성은 `session_routine` 편집과 달리 현재 outbox 대상이 아니다 | "루틴을 새로 만드는 건 인터넷이 연결된 뒤에 할 수 있어요." |
| 빈 | 프로그램 없음(선행 404) | [그래도 운동하기]를 렌더하지 않는다(빈 ①의 온보딩 카드만) | — |

- 즉석 세션도 **프로그램에 속하고 `user_id`에 매달린다.** 만들어진 뒤에는 평소 루틴 화면(S4)과 **완전히 같게** 동작한다(별도 화면·별도 규칙을 만들지 않는다).
- **AC-S3-4** `today.status = rest`이면 [그래도 운동하기]가 보이고, `workout`·`done`이면 DOM에 없다.
- **AC-S3-5** 부위 시트에 부위 버튼 6개가 보이고, `streak_days >= 7`이면 회복 안내와 "의료적 조언이 아니에요" 고지가 함께 보이며 **버튼은 여전히 눌린다**.
- **AC-S3-6** 부위를 고르면 세션이 만들어지고 루틴 화면으로 이동한다. 이미 오늘 세션이 있으면 새로 만들지 않고 그 세션으로 이동한다.
- **AC-S3-7** 생성 요청 중에는 부위 버튼이 비활성이고, 연타로 세션이 2개 만들어지지 않는다.

#### 2.4.1 세트 행 구조 — 최대 2줄 (F1-0)

> 문제: 세트 1개가 4줄(무게·횟수 / RIR / 배지 / 목표·직전)로 흩어지면 운동 중에 한눈에 안 들어오고,
> 세트가 15개 쌓이는 화면이라 줄 하나가 화면 전체 높이를 좌우한다.

| 줄 | 담는 것 | 규칙 |
|---|---|---|
| **1줄차(주)** | 세트 번호 · 무게 · 횟수(또는 유지 시간) · **RIR** · 완료 체크 | **조작 대상만** 둔다. 높이 = 입력칸 높이(44px) |
| **2줄차(보조)** | `목표 {…} · 직전 {…}` **한 줄** | 12px, 1줄 `truncate`. 폭이 모자라면 **직전이 먼저 잘린다**(목표가 우선). 목표·직전이 둘 다 없으면 **줄을 만들지 않는다** |
| **우측(2줄 span)** | 완료 체크 버튼 | **48×48px**, 행 오른쪽 끝(§8 엄지 궤적) |

**그리드 계약과 최종 실측**(M-UIb Sprint 3, `AFC_TEST_TODAY=2026-08-21`)

미완료 행과 펼친 완료 행은 `16px minmax(0,1fr) minmax(0,1fr) 46px 48px`의 명시적 5열 그리드와
열 간격 6px을 쓴다. 아래 값은 생성된 `mobile-metrics.*.json`의 브라우저 실측값이며 가변 열은 반올림했다.

| 요소 | 계약 | Chromium mobile 390×844 | WebKit iOS 393×660 | 비고 |
|---|---:|---:|---:|---|
| 세트 번호 | 16px | 16px | 16px | 화면에는 숫자만, 접근 이름에는 "n세트"를 남긴다 |
| 무게 입력 | `minmax(0,1fr)` | 90px | 92px | 단위 접미사 없음 |
| 횟수 입력 | `minmax(0,1fr)` | 90px | 92px | 단위 접미사 없음 |
| RIR 필드 | 46px | 46px | 46px | 한 자리 값 + 최소 24px 셰브론 타깃 |
| 완료 체크 | 48px | 48×48px | 48×48px | 미완료·완료·펼친 완료 모두 동일(D-16) |
| 열 간격 | 6px × 4 | 6px × 4 | 6px × 4 | — |
| **행 바깥 크기** | 높이 ≤96px | **332×82px** | **335×82px** | 패딩·테두리 포함 |

> **단위 접미사(`kg`·`회`)는 입력칸에 두지 않는다.** 단위는 접근 이름(`"…무게, 킬로그램"`),
> 2줄차 보조 텍스트, 완료 축약 행(`62.5kg × 9회`)에 남는다. 즉 스크린리더 사용자와 기록을 읽는
> 시점에는 단위가 그대로 보이고, 입력 중에만 생략된다.

- `metric = time`: 시간 입력이 2~4열을 span하고 RIR은 렌더하지 않는다(§5.4).
- 자체중량: 빈 무게 칸을 남기지 않고 횟수 입력이 2~3열을 span한다(§5.3).
- `flex-wrap`이나 RIR의 2줄 이동은 쓰지 않는다. 360px에서도 두 가변 입력 열만 함께 줄고, 읽기용 보조 문구는 `truncate`한다.

**배지 중복 제거**(F1-0)

| 배지 | 위치 |
|---|---|
| `무게 미정`(BASELINE) · `자체중량` · 근거(`reason_code`) | **운동 카드 헤더에 1회만.** 세트 행에는 반복하지 않는다 |
| 예외 | 같은 카드 안에서 세트마다 종류가 다를 때만(예: 1세트만 BASELINE) **그 세트에만** 행 배지를 둔다 |
| `완료` | 행 배지로 만들지 않는다. 축약 행의 텍스트 끝에 `· 완료`로 들어간다(§2.4.3, §7.6 "색만으로 구분 금지" 충족) |
| 통증 점수 | 카드 헤더의 진행·배지 줄 |

**직전 기록 압축**(F1-0)

| 상황 | 표기 |
|---|---|
| 기본 | 2줄차에 `목표 8~10회 · 직전 62.5kg×6` (× 양옆 공백 없음) |
| 입력칸이 빈 세트(무게 미정 등) | 입력칸 placeholder는 `무게`·`횟수` 그대로 둔다. **직전 값을 placeholder로 넣지 않는다** — 회색 숫자를 입력값으로 오해할 위험이 실제 기록 오염으로 이어진다 `[해석]` |
| 직전 기록 없음 | `직전` 부분을 통째로 생략한다(`직전 -`·`직전 없음` 금지) |
| 출처 | 이번 세션에서 완료한 **같은 운동의 직전 세트**. 지난 세션 기록은 로컬 미러가 붙는 STEP 6부터 |

- **AC-SET-1** 미완료 세트 행은 2줄 이하이고 실측 높이가 **96px 이하**다(390×844).
- **AC-SET-2** 같은 운동 카드 안에서 `무게 미정` 배지가 2회 이상 렌더되지 않는다(`자체중량`도 동일).
- **AC-SET-3** 360px 폭에서도 두 가변 입력 열이 함께 줄어 1줄차가 가로 스크롤 없이 들어가고, RIR은 46px 열을 유지하며 행은 3줄이 되지 않는다.
- **AC-SET-4** 목표·직전이 모두 없는 세트에는 2줄차가 DOM에 없다.

#### 2.4.2 RIR 단일 필드 (F1-1, 2차 개정)

> 기존: 숫자 입력칸 + 네이티브 `select` **2개 컨트롤**이 같은 값을 보여줬다 → 중복이고 폭을 먹었다.
> 확정: **하나의 필드**로 합친다. 기존 동작(0~6 거부·미입력 null·목표 병기)은 그대로 유지한다.

| 항목 | 규칙 |
|---|---|
| 구조 | 입력칸 1개 + 칸 **안쪽 우측**의 셰브론 버튼. 테두리 하나로 묶여 **시각적으로 필드 1개**로 보인다 |
| 직접 입력 | `type="text" inputmode="numeric" maxLength=1`. 0~6만 받는다. 그 밖(`7`~`9`, 문자, 음수, 소수점)은 **거부** — 값이 바뀌지 않는다(**clamp 금지**: `7`을 쳐도 `6`이 되지 않는다) |
| 지우기 | Backspace/Delete로 비우면 `null`(모름). **요청 바디에 키가 실리지 않는다**(0으로 바꿔 보내지 않는다) |
| 목록에서 고르기 | 셰브론 탭 → 하단 시트 **"RIR 고르기"**. 칩 8개: `모름` `0` `1` `2` `3` `4` `5` `6`(3열 그리드, 각 44px 이상). 고르면 **즉시 닫고** 입력칸으로 포커스 복귀 |
| 시트 보조 문구 | "세트를 끝냈을 때 몇 회 더 할 수 있었는지예요. 잘 모르겠으면 비워 두세요." |
| 목표 표기 | 2줄차 보조 텍스트에 `RIR 목표 2`. `target_rir`이 null이면 표기를 **렌더하지 않는다**. 시트에서는 목표에 해당하는 칩에 `목표` 표시 |
| 프리필 | **하지 않는다.** RIR은 사용자가 느낀 값이라 추천값을 넣으면 그대로 확정될 위험이 크다(무게·횟수 프리필과 다르다) |
| 시간 종목 | 렌더하지 않는다(§5.4, AC-E-4) |
| 완료 후 | 축약 행에 `RIR 2`로 들어간다. 미입력이면 그 조각을 생략한다 |

**왜 `datalist`도 네이티브 `select`도 아닌가** `[해석]`

| 후보 | 판단 |
|---|---|
| `<input list>` + `<datalist>` | **탈락.** 모바일 브라우저마다 표시가 다르고(iOS는 키보드 위 제안 줄), **탭으로 목록을 여는 신뢰할 만한 방법이 없다.** 보조기술의 combobox 낭독도 갈린다 → F1-1의 "한 손으로 고를 수 있어야 한다"를 보장하지 못한다 |
| 네이티브 `<select>` 단독 | **탈락.** 목록은 확실하지만 **모바일에서 직접 타이핑이 불가능**하다(타입어헤드는 데스크톱 전용) → F1-1의 "직접 칠 수도 있고"를 잃는다 |
| ARIA 1.2 combobox + listbox 자작 | **탈락.** 요구는 다 만족하지만 roving focus·`aria-activedescendant`를 직접 구현해야 해 세트 15개짜리 화면에 비해 비용이 크다 |
| **입력칸 + 셰브론 → 하단 시트** | **채택.** 이미 있는 Sheet/Chip 컴포넌트를 재사용하고(포커스 트랩·Esc·배경 잠금 검증됨), 시트가 화면 하단에서 올라와 엄지 반경(§8)에 들어온다. 네이티브 `select`도 모바일에서는 하단 휠을 띄우므로 **모달성 비용은 같다**. 타이핑과 고르기가 둘 다 된다 |

**키보드·스크린리더**

| 항목 | 규칙 |
|---|---|
| 입력칸 접근 이름 | `aria-label="{운동} {n}세트 RIR, 남은 반복 수. 0에서 6, 비워 두면 모름"` |
| 목표 연결 | **2줄차 보조 텍스트의 "RIR 목표 2"** 를 `aria-describedby`로 연결한다(라벨을 길게 만들지 않는다). 배치 근거는 AC-RIR-4 참조. 오류 문구가 2줄차를 대체하는 동안에는 연결을 끊어 **dangling id를 만들지 않는다** |
| 셰브론 | `<button aria-label="{운동} {n}세트 RIR 고르기" aria-haspopup="dialog" aria-expanded="false" tabindex="-1">` — **탭 순서에서 뺀다**(세트 15개면 정거장이 15개 늘어난다. ARIA APG의 combobox 토글과 같은 처리) |
| 시트 열기(키보드) | 입력칸에서 `Alt + ↓`. 키보드 사용자는 타이핑이 더 빠르므로 시트는 보조 경로다 |
| `↑`/`↓` | 값이 있을 때만 ±1, **0과 6에서 멈춘다**(순환 금지). 비어 있으면 아무 일도 하지 않는다 |
| 포커스 진입 | 기존 값 전체 선택(지우고 다시 치지 않아도 덮어쓴다) |
| 거부된 입력 | 흔들기·에러 문구 없이 **값이 그대로 유지되는 것으로 끝**. 자주 눌리는 자리에 경고를 쌓지 않는다 `[해석]` |
| 탭 순서 | 무게 → 횟수 → RIR 입력칸 → 완료 체크 |

- **AC-RIR-1** RIR은 세트당 **하나의 필드**로 보인다(입력칸과 별도 드롭다운이 나란히 있지 않다).
- **AC-RIR-2** `7`·`-1`·`2.5`·`a`를 입력해도 값이 바뀌지 않는다(`7` 입력 후 `6`이 되지 않는다).
- **AC-RIR-3** RIR을 비워 둔 채 완료 체크하면 저장·전송 페이로드에 RIR 키가 **없다**(0이 들어가지 않는다).
- **AC-RIR-4** `target_rir`이 있으면 **"RIR 목표 {n}"이 2줄차 보조 텍스트에 보이고**, RIR 입력칸이 `aria-describedby`로 그 텍스트를 가리킨다. null이면 표기와 연결이 모두 DOM에 없다.
  > **확정 2026-08-06, M-UIb 실측 재확인 2026-08-15**: 46px RIR 열은 한 자리 값과 셰브론만 소유한다.
  > 목표를 같은 열에 더 넣지 않고 **2줄차 배치 + `aria-describedby` 연결**을 정식 방식으로 유지한다.
- **AC-RIR-5** 셰브론으로 연 시트에서 `모름`을 고르면 값이 비워지고 포커스가 입력칸으로 돌아온다.
- **AC-RIR-6** 키보드만으로 입력·수정·지우기가 된다(↑/↓ ±1, Backspace로 모름).
- **AC-RIR-7** 셰브론은 Tab 순서에 없다(세트 3개 화면에서 Tab 정거장이 세트당 3개다: 무게·횟수·RIR).

#### 2.4.4 운동 카드 헤더 · 3항목 앵커 메뉴 (F5, D-14·D-17)

카드 헤더에는 `⋯` 트리거 하나를 두고, 카드에 앵커된 **교체 / 통증 기록 / 삭제** 3항목 메뉴를 연다.
**건너뛰기는 이번 범위에 없다.** [운동 추가]는 종전대로 목록 하단의 별도 세션 액션이다.

| 요소 | 위치 | 규칙 |
|---|---|---|
| 운동 이름 | 헤더 좌측 | 남는 폭 전부. 길면 **2줄까지 줄바꿈**(말줄임 금지 — 종목명이 잘리면 무슨 운동인지 모른다) |
| `⋯` 메뉴 트리거 | 헤더 우측 | **48×48px**. `aria-label="{운동} 메뉴"` + `aria-haspopup="menu"` + `aria-expanded`. 메뉴는 트리거에 시각적으로 앵커된다 |
| [교체] 메뉴 항목 | 메뉴 | 활성 시 교체 팝업(M-2)을 연다. 기록이 있으면 포커스 가능한 `aria-disabled="true"` |
| [통증 기록] 메뉴 항목 | 메뉴 | 기록 유무와 관계없이 **항상 활성**. 기록 후 라벨은 `통증 5점 수정`처럼 현재 상태를 포함한다 |
| [삭제] 메뉴 항목 | 메뉴 | 활성 시 확인 시트(M-4)를 연다. 기록이 있으면 포커스 가능한 `aria-disabled="true"` |
| [운동 추가] | 카드가 아니라 **세트 목록 하단** | 카드 단위 동작이 아니라 세션 단위 동작이라 카드 밖에 둔다 |
| 진행·배지 줄 | 헤더 아래 | `{완료}/{전체} 세트 완료` + 근거 배지 + `무게 미정`/`자체중량` 배지 + 통증 점수 배지 |

> 이 메뉴는 `role="menu"`인 **비모달 popover**다. `role="dialog"`·포커스 트랩을 쓰는 중간 [편집] 시트를 다시 만들지 않는다.
> 키보드·닫기·포커스 복귀와 타이머 시트 충돌 규칙은 §7.2.1이 권위다.

| 되돌리기 | **제공하지 않는다** `[해석]` — 다시 추가하면 순서가 맨 뒤로 가고(계약상 `order_index` 지정 불가) 세트 구성이 그대로 복원된다는 보장이 없다. "실행 취소"라고 부를 수 없는 것을 그렇게 부르지 않는다. 대신 확인 시트 한 단계로 막는다 | — |

- **AC-DEL-1** 운동 카드에 `⋯` 메뉴 트리거가 있고 실측 44×44px 이상이다.
- **AC-DEL-2** 메뉴의 [삭제] 1회 선택으로는 삭제되지 않는다(확인 시트가 뜬다). 시트의 기본 포커스는 [취소]다.
- **AC-DEL-3** 완료 체크된 세트가 있는 운동의 [교체]·[삭제] 항목은 `aria-disabled="true"`이고 DOM에서 제거되지 않는다(방향키로 포커스가 간다).

- **AC-DEL-5** 삭제 성공 시 `role="status"`로 "{운동}을 루틴에서 뺐어요"가 낭독된다.
- **AC-DEL-6** 삭제 경로는 3항목 메뉴의 [삭제] **하나뿐**이다. 중간 [편집] 시트와 [건너뛰기] 항목은 없고, 교체·추가 팝업에도 삭제 항목이 없다.

## 3. 에러 처리 매핑

### 3.0 원칙

1. **서버 `error.message`를 사용자에게 그대로 노출하지 않는다.** STEP 4 메시지는 개발자용 해라체이고(`"세션을 찾을 수 없다."`) 일부는 식별자를 포함한다(`운동을 찾을 수 없다: e_xxx`). 화면 문구는 **아래 표의 문구를 쓴다**.
2. `error.code`(`VALIDATION_ERROR`/`NOT_FOUND`/`CONFLICT`/`INTERNAL_ERROR`/`NOT_IMPLEMENTED`)는 **로그·계측용**이다. 화면에 렌더하지 않는다.
3. **예방 > 복구.** 400/409의 대부분은 UI가 애초에 잘못된 요청을 못 만들게 하면 발생하지 않는다(§3.3).
4. 오류 문구는 `원인 + 다음 행동` 2문장을 넘기지 않는다.

### 3.4 세션 한정 세트 추가 안내

Sprint03의 세트 추가 버튼 라벨은 `세트 추가`다. 아래 표는 기존 운동 추가·교체 안내와 구분하며, 자격 판단과 전송 계약은 `FEATURE_IMPROVEMENTS_CONTRACT.md` 및 OpenAPI를 따른다.

| 확인한 상태 | 사용자 문구 | 표시·동작 |
|---|---|---|
| `append_eligibility` missing/null 또는 자격 정보 불충분 | "세트를 추가할 수 있는지 확인하지 못했어요. 다시 불러와 주세요." | 추가 비활성 + 카드 인라인 사유, 기존 [다시 불러오기] |
| 명시된 blocked/`unsafe_assistance_snapshot` | "이 운동은 지금 세트를 추가할 수 없어요." | 추가 비활성 + 카드 인라인 사유 |
| 세트 수 상한 | "세트 수는 1~10 사이로 정해 주세요." | E-8 문구 재사용, 추가 비활성 |
| append의 날짜 비자격(UTC 오늘이 아닌 세션) | "세트는 오늘 운동에만 추가할 수 있어요." | append에만 사용. 기존 다른 편집 동작·읽기 전용 UI·SESSION_COMPLETED 문구 유지. 오늘의 completed 명시 편집에서 추가를 막지 않음 |
| 서버가 `source_changed`를 반환하고 실제 재조회가 배선됨 | "다른 곳에서 먼저 바뀐 것 같아요. 최신 상태로 다시 불러올게요." | §3.1 기본409 문구와 재조회 재사용. 원 append intent의 source/revision은 자동으로 바꾸지 않음 |

- invalid raw 때문에 reader가 null을 반환해도 첫 문구를 사용한다. 그 원인을 위한 별도 화면 상태나 문구를 만들지 않는다.
- **통증·INVALID_INPUT 문구를 이 자리에 재사용하지 않는다.** 자격 정보의 부재나 blocked 판정은 사용자의 통증·잘못된 입력을 증명하지 않는다.
- **원인을 모르는 상태에서 네트워크 원인을 단정하지 않는다.** 첫 문구에 "연결 후"를 붙이지 않으며, 기존 `OFFLINE_MESSAGE`의 "연결되면 자동으로 이어서 진행할게요" 약속과 충돌하는 별도 수동 재연결 절차를 만들지 않는다.
- 강제 운동 교체, 새 복구 화면, 건강 판정, 두 탭 전용 안내를 추가하지 않는다. 서버의 개발자용 message/reason을 사용자 문구로 그대로 노출하지 않는다.

## 4. 휴식 타이머 상세 (F2 / F3 / F4)

서버 저장이 없는 **순수 클라이언트 상태**다(FEATURES_UX "데이터·계약 영향"). 추천 휴식값 = 그 세트의 `planned_set.rest_sec`.

### 4.1 상태 머신

```
closed ──(세트 완료 체크)──> running ──(remaining <= 0)──> finished
   ^                            │                              │
   └──── [휴식 종료] / Esc ──────┴───── [닫기] / [다음 세트] ────┘
```
- **일시정지 상태는 없다**(F2~F4에 정지 기능이 없다 — 임의 추가 금지).
- 여러 타이머가 동시에 뜨지 않는다. `running` 중 다른 세트를 체크하면 **새 세트 기준으로 타이머를 교체**한다 `[해석]`.

### 4.2 시간 계산(단일 진실값)

| 변수 | 정의 |
|---|---|
| `totalSec` | 현재 총 휴식 시간. 시작값 = `rest_sec`. F3 가산 시 갱신 |
| `endsAt` | 절대 종료 시각(epoch ms). 시작 시 `Date.now() + totalSec*1000` |
| `remainingSec` | `Math.max(0, Math.ceil((endsAt - Date.now()) / 1000))` |
| `elapsedSec` | `totalSec - remainingSec` |

- **누적 감산 금지**: `setInterval`마다 `remaining -= 1` 하지 않는다(드리프트·백그라운드 스로틀로 어긋난다). **항상 `endsAt`에서 다시 계산**한다.
- 틱 주기 200ms. 화면 텍스트는 `remainingSec`가 바뀔 때만 갱신.

### 4.3 표기

| 항목 | 규칙 | 예 |
|---|---|---|
| 카운트다운 | `분:초`, 초는 2자리 zero-pad, 분은 pad 없음 | `1:30`, `0:07`, `10:00` |
| 60초 미만 | 그대로 `0:45`(초만 크게 쓰지 않는다 — 자릿수 흔들림 방지) | `0:45` |
| 종료 | `0:00` + 상태 라벨 "휴식 완료" | — |
| 숫자 폰트 | tabular-nums 고정폭(값이 바뀌어도 폭이 흔들리지 않게) | — |
| 보조 라벨 | 상단에 "{운동 이름} {n}세트 후 휴식" | — |

### 4.4 진행 바

| 항목 | 규칙 |
|---|---|
| 값 | `percent = remainingSec / totalSec * 100` (100% → 0%) |
| 갱신 | 틱(200ms)마다 폭 갱신. CSS `transition: width 200ms linear`로 부드럽게 |
| `prefers-reduced-motion: reduce` | transition 제거, 1초 간격 계단식 갱신 |
| 시간 가산 시 | `totalSec` 재계산 후 **percent가 즉시 위로 점프**한다(F3: "새 총시간 기준으로 갱신"). 점프는 애니메이션 없이 즉시 반영 |
| 0 도달 | 폭 0%. 바를 숨기지 않는다(위치 흔들림 방지) |
| 접근성 | §7.3 — 바는 카운트다운 텍스트와 중복 정보이므로 `aria-hidden="true"` |

### 4.5 시간 증가 (F3)

버튼 4개: `+5초` `+10초` `+30초` `+1분`.

| 항목 | 규칙 |
|---|---|
| 동작 | 탭 즉시 `remainingSec`에 가산. 디바운스·쓰로틀 **없음**(연타가 그대로 누적, 예: +30초 3연타 = +90초) |
| 구현식 | `elapsed = totalSec - remainingSec` → `remainingNew = min(600, remainingSec + delta)` → `totalSec = elapsed + remainingNew` → `endsAt = Date.now() + remainingNew*1000` |
| 상한 | **남은 시간 기준 10분(600초)** `[해석]` — FEATURES_UX는 "합리적 상한(예: 10분)"만 정한다. 사용자가 보는 값이 남은 시간이므로 남은 시간에 건다 |
| 상한 부분 적용 | 상한에 걸리면 **가능한 만큼만 더한다**(예: 남은 580초 + 60초 → 600초). 요청을 통째로 무시하지 않는다 |
| 상한 도달 피드백 | ① 4개 버튼 `aria-disabled="true"` + 흐리게(포커스는 유지), ② 토스트 1회(중복 억제 3초): "휴식은 최대 10분까지 늘릴 수 있어요.", ③ 남은 시간이 600초 미만으로 내려가면 자동 재활성 |
| 눌러도 되는 시점 | `running` 상태에서만. `finished`에서는 4개 버튼을 숨긴다 `[해석]` |
| 시각 피드백 | 탭마다 카운트다운 숫자에 짧은 강조(120ms). reduced-motion이면 생략 |

### 4.6 휴식 종료 (F4)

| 항목 | 규칙 |
|---|---|
| 위치 | 팝업 **하단 전폭 버튼**(엄지 반경, §8) |
| 라벨 | `휴식 종료` |
| 동작 | 확인 없이 **즉시** 타이머 종료 + 팝업 닫기 + 다음 미완료 세트 행으로 포커스·스크롤 이동 |
| 키보드 | `Esc` = [휴식 종료]와 동일 `[해석]` |
| 배경 탭 | 배경(딤) 탭으로도 닫는다. 동작은 [휴식 종료]와 동일 |

### 4.7 0초 도달

| 항목 | 규칙 |
|---|---|
| 팝업 | **자동으로 닫지 않고** `finished` 상태로 전환한다 `[해석]` — FEATURES_UX는 "자동 닫힘 **또는** '다음 세트' 준비 상태" 두 갈래를 준다. 아래 소리·진동은 **전경에서 끝났을 때만** 나고 그마저 실패할 수 있으므로(무음 모드·미지원·거부), 화면을 유일하게 확실한 통지 수단으로 둔다. 자동으로 닫으면 백그라운드에서 끝난 경우 종료 사실이 **아무 데도 남지 않는다** |
| 화면 | `0:00` + "휴식 완료" + 하단 버튼이 [다음 세트]로 바뀜. +시간 버튼 숨김 |
| [다음 세트] | 팝업 닫고 다음 미완료 세트 입력칸으로 포커스 이동 |
| 알림 | **후보 기능에서 기본 활성.** 종료 시 짧은 비프 1회 + 진동 1회를 best-effort 로 시도한다. **설정 UI·권한 요청 UI를 두지 않는다** — 켜고 끄는 화면은 이 범위가 아니다. FEATURES_UX "안전"의 *"옵션(기본 off 가능)"* 은 허용 문구이고, 이 표가 후보 단계의 확정값이다 |
| 알림 실패 | 미지원·권한 거부·정지된 오디오 컨텍스트는 **조용히 건너뛴다**. 소리·진동 실패가 세트 완료·기록 저장·다음 세트 진행을 막지 않는다. 비프와 진동은 서로 독립이라 한쪽이 실패해도 다른 쪽은 시도한다 |
| 알림 조건 | **전경에서 종료를 관측했을 때만** 재생한다. 백그라운드에서 이미 끝난 타이머는 복귀 시점에 **늦게 재생하지 않고** `finished` 화면만 보여준다 (브라우저 자동재생·진동 제약). 판정은 관측 순간의 `visibilityState` 만으로는 부족하다 — 숨은 탭은 틱이 스로틀돼 복귀 직후에야 처음 관측되므로, **끝난 시각이 마지막 전경 복귀보다 앞서면** 백그라운드 종료로 본다 |
| 알림 횟수 | 한 타이머당 1회. 틱·`visibilitychange`·`focus`·`pageshow` 재계산이나 재렌더로 늘어나지 않는다. 휴식을 더해 `endsAt` 이 바뀌거나 다음 세트로 새 타이머가 열리면 그 타이머에서 다시 1회다. 위 조건으로 **건너뛴 경우에도 그 타이머는 소진**된다(나중에 울리지 않는다) |
| 백그라운드 알림 | 앱이 전경에 없을 때 OS 알림으로 알리는 것은 **이 범위가 아니다**(Service Worker 알림·권한 UI·타이머 지속 저장 포함). 별도 트랙 소유다 |
| 초과 시간 | 0:00에서 멈춘다. 경과 시간 카운트업은 하지 않는다(스펙에 없음) |

### 4.8 백그라운드 / 탭 전환 복귀 보정

| 이벤트 | 처리 |
|---|---|
| `visibilitychange` → visible | `endsAt`으로 `remainingSec` 재계산 → 0 이하면 즉시 `finished`로 전환 |
| `focus`, `pageshow`(bfcache 복귀 포함) | 위와 동일 재계산 |
| 백그라운드 동안 | 타이머 상태는 메모리 + **기존 Dexie `syncMeta`의 `rest-timer:{sessionId}` 레코드**에 보존한다(새 store·스키마 버전을 만들지 않는다). 남은 시간은 저장하지 않고 언제나 `Date.now()`와 `endsAt`으로 계산하므로 새로고침·복귀에서 이어진다 |
| 앱 완전 종료 후 재진입 | **best effort로 복원한다.** 이미 만료됐어도 종료 후 `REST_MAX_SEC`(10분) 이내면 0:00 `finished`로 복원하고 **자동으로 닫지 않는다**(§4.7). 그보다 오래됐거나 다른 세션·손상·모르는 버전이면 복원하지 않고 그 레코드를 지운다(유령 타이머 방지). 마지막 저장이 디스크에 닿기 전에 OS가 프로세스를 죽이면 그 타이머는 복원되지 않는다 |
| 숨김 상태 종료 알림 | 페이지가 살아 있고 실제로 숨겨져 있으며 알림 권한이 **이미** `granted`이고 서비스워커 등록이 있을 때만 1회 시도한다. 앱 안에 권한을 청하는 경로가 없어 사용자가 브라우저 설정에서 미리 허용해야 한다. 잠금화면 문구는 운동·수치를 담지 않는 고정 문구다. OS 예약 알람이 아니므로 프로세스가 죽으면 오지 않는다 |
| 시계 되돌림 등 이상값 | **진행 중(메모리) 타이머**는 `remainingSec > totalSec`이면 `totalSec`으로 clamp한다(표시만 보정). **저장분을 읽을 때**는 다르다 — 아래 참조 |
| 레코드 계약(v2) | `{ session_id, planned_set_id, title, total_sec, ends_at, saved_at }`. `saved_at`은 저장 시각이고 시간 검증의 기준점이다. `total_sec`은 **양수**이며 상한이 없다 — `addRest`가 `elapsed + remaining`으로 누적하므로 600초 휴식에서 100초 뒤 +300하면 총 700이 정상이다. 시작 시각 `ends_at − total_sec×1000`이 `saved_at`보다 미래이거나 epoch 이전이면 손상으로 보고 거절한다 |
| legacy v1 | **읽지 않는다.** 버전이 다르면 fail-closed로 거절하고 지운다. 최대 10분짜리 값이라 잃는 비용이 작고 다음 세트에서 새로 생긴다 |
| 시계가 뒤로 간 기기 | **읽는 시점의 시계가 `saved_at`보다 뒤면 그 레코드를 버린다(관용 0).** 무제한 되돌림 관용과 좀비 차단은 동시에 만족할 수 없어 폐기 쪽으로 정책을 잠갔다 — 잃는 것은 타이머 하나지만, 반대쪽은 사용자가 지울 수 없는 오버레이가 화면을 가린다 |
| 복구 자격 | 존재하는 세트 id 전부가 아니다. 기본은 **서버가 준 사실**(세션이 `completed`가 아니고 그 planned set에 `performed_set`이 있을 때)이고, 그 위에 **durable 로컬 의사**를 얹는다 — `drafts.completed`는 `commitDraftBatch`가 `outbox`와 같은 IndexedDB 트랜잭션에 커밋한 값이라 sync 전에도 최신 사실이다. 로컬 행이 있으면 그 값이 이기고, 없으면 서버 사실을 쓴다. Zustand 낙관 상태는 쓰지 않는다. 그래서 오프라인 완료 직후 새로고침해도 타이머가 복구되고, 오프라인 완료 취소 뒤에는 저장분 삭제가 실패했더라도 다시 뜨지 않는다. sync가 끝나 로컬 행과 서버가 일치하면 자연히 수렴한다. **로컬 의사와 저장분은 하나의 IndexedDB 트랜잭션에서 함께 읽고, 자격 없는 기록의 삭제도 그 안에서 한다** — 따로 읽으면 다른 탭의 원자적 커밋과 섞여 정상 타이머를 지우거나 취소한 타이머를 올린다. 로컬 의사를 **읽지 못하면 `unknown`**이다: 그때는 올리지도 지우지도 않고 다음 진입이 다시 판단한다(읽기 실패를 "행 없음"으로 낮추면 서버의 stale 사실로 되돌아간다) |
| terminal 정리 실패 | 닫기·완료취소·세션종료는 저장분 삭제 결과를 확인한다. 닫기는 실패 시 시트를 유지하고 재시도할 수 있다. 완료취소·세션종료는 **업무 쓰기를 되돌리지 않고**(기록은 그대로) 안내만 띄우며, 남은 레코드는 위 복구 자격이 막는다 |
| 오프라인 세트 id 승격 | `/sync`의 authoritative 커밋 트랜잭션이 저장분의 planned-set id를 옮기고, **같은 트랜잭션에 `rest-timer-alias:` 별칭 레코드**를 남긴다(새 store·스키마 버전 없음). 타이머 저장은 **자기 쓰기 트랜잭션 안에서** 그 별칭을 읽어 canonical id로 기록하므로, 매핑이 먼저 커밋되든 저장이 먼저 커밋되든 최종 행은 서버 id다 — 화면이 없어도, 다른 탭이어도 성립한다. 롤백되면 승격도 별칭도 없던 일이 된다. 손상·모르는 버전 별칭은 무시하고 원래 id를 쓴다. **별칭의 수명은 시간이 아니다** — 보존 기간을 두면 같은 매핑이 다시 왔을 때 방금 갱신한 별칭을 옛 스냅샷 기준으로 지웠고, 오래 열린 탭이 그 뒤에 correlation id로 저장해 durable correlation 행이 남았다. 명시적 lifecycle owner(세션 종료·404/410·캐시 purge)를 붙이려면 별칭이 어느 세션 것인지 알아야 하는데 `PlannedSetMapping`에 `session_id`가 없어 증명할 수 없다. 그래서 별칭을 유지하고, 무한 증가는 correctness와 분리된 housekeeping 과제로 남긴다 |

### 4.9 수용 기준

- **AC-T-1** `1:30`처럼 분:초로 표기되고, 초는 항상 2자리다.
- **AC-T-2** 진행 바가 시작 100%에서 종료 0%까지 단조 감소한다(시간 가산 시점 제외).
- **AC-T-3** `+30초`를 1초 안에 3번 연타하면 남은 시간이 정확히 90초 늘어난다.
- **AC-T-4** 남은 시간 590초에서 `+1분`을 누르면 600초가 되고, 상한 안내가 1회 뜨며, 4개 버튼이 비활성된다.
- **AC-T-5** [휴식 종료]는 확인 단계 없이 **한 번의 탭**으로 닫는다. 정상 저장 상태에서는 체감상 즉시다. 다만 닫기는 **저장분 삭제가 실제로 끝난 뒤** 일어난다 — 그 전에 닫으면 새로고침에서 닫은 타이머가 다시 떠 기록 편집을 가린다(실측). 삭제가 실패하면 **시트를 유지하고** 안내를 띄우며, 같은 버튼이 재시도다.
- **AC-T-6** 타이머 실행 중 탭을 60초 동안 백그라운드로 두었다 돌아오면 남은 시간이 정확히 60초 줄어 있다.
- **AC-T-7** 백그라운드에서 0초가 지난 뒤 복귀하면 `finished` 화면이 보인다(카운트다운이 음수로 가지 않는다).
- **AC-T-8** 화면을 보고 있는 상태에서 0초에 닿으면 비프와 진동이 **각각 정확히 1회** 발생한다. 그 뒤 틱·`focus`·`pageshow`·`visibilitychange` 를 아무리 더 밟아도 늘지 않는다.
- **AC-T-8a** 백그라운드에서 0초가 지난 뒤 복귀하면 `finished` 화면만 보이고 **소리·진동은 발생하지 않는다**(늦은 재생 금지). 그 타이머는 이후에도 울리지 않는다.
- **AC-T-8b** 오디오·진동이 미지원이거나 거부돼도 세트 완료·기록·다음 세트 진행이 그대로 동작한다.
- **AC-T-9** 타이머가 떠 있는 동안에도 뒤 배경의 기록 값은 소실되지 않는다.

## 5. 엣지 케이스 렌더링 규칙 (중요)

### 5.1 판별 순서

세트 행을 그리기 전에 **반드시 이 순서로** 분기한다. `recommended_weight` 값만 보고 그리면 안 된다.

```
1) metric === "time"                      → 시간 종목   (§5.4)
2) recommended_weight === null            → 자체중량    (§5.3)
3) recommended_weight === 0 && reason_code === "BASELINE" → 무게 미정 (§5.2)
4) 그 외                                   → 일반(가중·반복)
```
- `metric`의 1차 출처는 카탈로그 `Exercise.metric`이다. 카탈로그를 아직 못 받았다면 `target_time_low_sec != null`을 폴백 판별로 쓴다.
- `PlannedSet`의 반복 축(`target_reps_*`, `recommended_reps`, `target_rir`)은 nullable이다. **null인 축은 렌더하지 않는다**(`-`, `0`, `null` 출력 금지).

### 5.2 `BASELINE` 첫 세션 — `weight: 0` (0kg 표시 금지)

> 추천 엔진은 기록이 없을 때 `weight = 0` + `reason_code = "BASELINE"`을 반환한다. **이건 "0kg을 들어라"가 아니라 "무게 미정"이다**(PROGRESS STEP 3 계약 메모).

| 요소 | 규칙 |
|---|---|
| 무게 표시 | `무게 미정` 배지를 **운동 카드 헤더에 1회만** 둔다(세트 행 반복 금지, §2.4.1). **`0kg`·`0`·`-` 절대 금지** |
| 무게 입력칸 | 빈 칸 + placeholder `무게`. **프리필하지 않는다** |
| 보조 문구(운동 카드 1회) | "첫 세션이라 추천 무게가 아직 없어요. 가볍게 워밍업하면서 오늘의 무게를 정해 보세요." |
| 완료 체크 | 무게가 비어 있으면 체크를 막고 입력칸으로 포커스 이동 + "무게를 입력해 주세요." |
| 반복 | `recommended_reps`/`target_reps_low~high`는 정상 표시 |
| RIR | 정상적으로 묻는다 |
| 2세트 이후 | 같은 운동의 앞 세트에 입력한 무게를 다음 세트 입력칸에 프리필한다 `[해석]`(같은 세션 내 반복 입력을 줄이기 위함) |

- **AC-E-1** `reason_code = BASELINE`인 세트 어디에도 문자열 `0kg`이 렌더되지 않는다.
- **AC-E-2** 무게가 비어 있는 BASELINE 세트는 완료 체크가 되지 않는다.

### 5.3 맨몸(자체중량) 종목 — `recommended_weight: null`

> 엔진은 맨몸 종목에 부하를 처방하지 않는다(`weight = null`). 진행은 반복으로 한다(`REPS_UP_BODYWEIGHT` 등).

| 요소 | 규칙 |
|---|---|
| 무게 표시 | `자체중량` 배지를 **운동 카드 헤더에 1회만** 둔다(세트 행 반복 금지, §2.4.1). `0kg`·빈칸 금지 |
| 무게 입력칸 | **표시하지 않는다.** 추가 부하(웨이트 벨트) 입력란은 스펙에 없으므로 만들지 않는다 |
| 저장값 | `actual_weight = null` |
| 반복 | `target_reps_low~high` 범위 + `recommended_reps` 프리필 |
| RIR | 정상적으로 묻는다(엔진은 부하 판정에 쓰지 않지만 `too_hard` 판정에는 쓴다) |
| 레이아웃 | 무게 칸이 사라진 만큼 반복 입력칸을 넓힌다. 빈 칸을 남기지 않는다 |
| 볼륨 표기 | §10 C-6 `[확인 필요]` — 자체중량 세트의 볼륨 산입 규칙 미정. 확정 전까지 요약 화면에서 별도 문구를 만들지 않는다 |

- **AC-E-3** 자체중량 세트에는 무게 입력칸이 DOM에 없다.

### 5.4 시간 종목 — `metric: "time"`

> 대상 예: 플랭크. 무게·반복 대신 **목표 유지 시간(초)** 으로 처방·기록한다. **RIR을 묻지 않는다**(엔진이 적용하지 않으며 수집도 생략).

| 요소 | 규칙 |
|---|---|
| 무게 | 표시·입력 모두 없음 |
| 반복 | 표시·입력 모두 없음 |
| 목표 | `target_time_low_sec ~ target_time_high_sec` → "목표 40~60초". 두 값이 같으면 "목표 40초" |
| 입력 | **시간(초) 입력 1칸**. `inputmode="numeric"`, 단위 접미사 `초` |
| 프리필 | `target_time_low_sec`를 프리필한다 `[해석]`(하단 = 최소 성공 기준) |
| RIR | **묻지 않는다.** RIR UI를 렌더하지 않는다(비활성이 아니라 미렌더) |
| 저장값 | `actual_time_sec`. `actual_weight`/`actual_reps`는 `null` |
| 휴식 타이머 | 동일하게 동작(§4) |

- **AC-E-4** `metric = time` 세트에 RIR 입력이 DOM에 없다.
- **AC-E-5** `metric = time` 세트의 완료 체크는 시간 값만으로 가능하다.

### 5.5 추천 근거(`reason_code`) → 사용자 문구

`PlannedSet`에는 `reason_code`만 있고 자유 텍스트 설명이 없다(`Recommendation.explanation`은 요약 화면 전용). 루틴 화면의 근거 배지는 아래 **클라이언트 매핑**을 쓴다.

| `reason_code` | 화면 문구 |
|---|---|
| `BASELINE` | 첫 세션이라 무게를 직접 정해요 |
| `WEIGHT_UP_REP_TARGET_MET` | 지난번 목표 반복을 모두 채워서 무게를 올렸어요 |
| `ADD_ONE_REP` | 무게는 그대로, 반복을 1회 늘려요 |
| `HOLD_RIR_LOW` | 지난번이 힘들어 보여 무게를 유지해요 |
| `TOO_HARD` | 지난번이 버거워서 무게를 조금 낮췄어요 |
| `RIR_TOO_EASY_INCREASE` | 여유가 있어 보여 무게를 올렸어요 |
| `RIR_TOO_HARD_REDUCE` | 강도가 높아 보여 부담을 줄였어요 |
| `REPS_UP_BODYWEIGHT` | 자체중량이라 반복 목표를 늘려요 |
| `PROGRESSION_CAP_BODYWEIGHT` | 반복이 충분히 늘어서 난도를 올릴 때예요 |
| `SUBSTITUTE_TOO_HARD_BODYWEIGHT` | 지금은 조금 버거워요. 보조 운동으로 바꿔 보세요 → [교체](F5 교체 팝업) |
| `TIME_UP` | 목표 시간을 채워서 조금 더 늘려요 |
| `TIME_HOLD` | 이번엔 같은 시간으로 유지해요 |
| `TIME_DOWN` | 목표 시간을 조금 낮췄어요 |
| `SUBSTITUTE_PAIN` | 통증이 기록돼서 다른 운동을 권해요 (+ 의료 조언 아님 고지) |
| `INVALID_INPUT` | (표시하지 않는다 — 근거 영역 숨김) |
| 목록 밖 값 | **근거 영역을 숨긴다.** 코드 원문 노출 금지 |

> **V2-REASON-01(2026-08-23)에서 6종을 이 표에서 뺐다.** 엔진이 emit하지 않는 코드를 사용자 문구 맵에
> 두면 소비자가 "가능한 응답"으로 처리하게 된다.
>
> - `RIR_ON_TARGET_HOLD` — **완전 제거.** on-target은 별도 reason 없이 더블 프로그레션으로 넘긴다는 것이 설계다.
> - `VOLUME_SPIKE_CAP`·`DELOAD_SUGGESTED`·`CALIBRATION_STALE` — **예약**(`RESERVED_REASON_CODES`).
>   기능 티켓에서 입력·emit·테스트와 함께 되살릴 때 문구도 같이 정한다.
> - `CALIBRATION_NEEDED`·`CALIBRATION_GRADUATED` — **추천 근거가 아니라 튜토리얼 상태다.**
>   UI 문구가 필요하면 `CalibrationStatus`(`not_started|in_progress|graduated|stale`) 기반으로 설계한다(`V2-RIR-01`).
>
> 저장된 구형 행에 이 코드가 남아 있어도 **목록 밖 값 규칙**이 그대로 적용돼 근거 영역이 비고 영문 코드는 노출되지 않는다.

**V2 추가 (ADR-70, 소유 티켓 V2-GATE-01)** — `LOAD_CALIBRATION_NEEDED`의 확정 문구:

> 첫 운동이라 추천 무게를 정하는 중이에요. 가벼운 무게부터 시작해 목표 반복을 3~4회 여유 있게 할 수 있는 무게를 입력해 주세요.

- **weight axis 전용**이다. `target reps`는 계속 표시한다 — 이 상태는 무게만 미정이라는 뜻이다.
- analysis·e1RM 근거로 취급하지 않는다(`analysis_gate`와 무관하게 첫 세션부터 표시).
- 목록 밖 값 숨김 규칙(AC-E-6)은 그대로 적용된다.
- 소유 분담: **V2-ENGINE-01**이 reason을 생성하고 골든으로 고정한다.
  **V2-GATE-01**이 이 표·웹 `REASON_TEXT`·단위 테스트·E2E를 갱신한다.
  V2-ENGINE-01 시점에는 이 문구가 아직 화면에 없다.

- **AC-E-6** 알 수 없는 `reason_code`가 와도 화면에 영문 코드가 노출되지 않는다.

| 표시 라벨 | 전송값 | 접근 이름(`aria-label`) |

### 6.3 선택 규칙

| 규칙 | 동작 |
|---|---|
| 초기 상태 | 8개 칩도 "해당 없음"도 **선택되지 않은 상태**로 시작한다("해당 없음"을 기본 선택하지 않는다 — 안전 질문에 답을 대신 넣지 않는다) |
| 배치 | "해당 없음"은 8개 칩 그리드 **아래에 따로** 둔다(같은 줄에 섞지 않는다). 배타 관계가 시각적으로 드러나야 한다 |
| 다중 선택 | 8개 칩은 서로 독립적으로 토글된다 |
| "해당 없음" 선택 | 다른 선택이 **모두 해제**되고 `pain_areas: []`로 전송된다 |
| "해당 없음" 선택 상태에서 부위 선택 | "해당 없음"이 자동 해제되고 그 부위가 선택된다 |
| 배타 강제 위치 | 두 방향 모두 **상태 변환 함수 한 곳**에서 처리한다(칩 이벤트 핸들러마다 흩어 놓지 않는다). 상태에 배타가 아닌 조합(`none = true` + `areas.length > 0`)이 **표현 자체로 불가능**해야 한다 |
| 아무것도 선택 안 함 | `pain_areas: []`로 전송(= "해당 없음"과 동일 결과). [다음]을 막지 않는다 `[해석]` |
| 선택 요약 | 칩 아래에 "{n}곳 선택됨" 표시(0이면 표시 안 함) |
| 전송 직전 검증 | 배열의 모든 값이 상수 8종에 속하는지 확인. 아니면 전송하지 않고 개발 로그만 남긴다(사용자 오류 아님) |

### 6.4 선택 결과 안내(다음 화면 연계)

- 통증 부위를 1개 이상 골랐으면 프로그램 확인 화면(S2)의 **제외 운동 섹션이 반드시 보인다**(§2.2).
- 제외 결과가 0건일 수도 있다(예: `wrist`는 제외 패턴이 없고 머신·케이블 우선 정렬만 한다). 이때 문구:
  "선택하신 부위 때문에 뺀 운동은 없어요. 대신 관절 부담이 적은 기구 위주로 골랐어요."

### 6.5 수용 기준

- **AC-P-1** 화면에 자유 텍스트 입력 요소가 0개다.
- **AC-P-2** "해당 없음"과 부위 칩은 절대 동시에 선택되지 않는다.
- **AC-P-6** 상호배타의 **양방향**이 성립한다: ① "해당 없음"을 켜면 선택돼 있던 부위 칩의 `aria-pressed`가 전부 `false`가 된다. ② 그 상태에서 부위 칩을 누르면 "해당 없음"의 `aria-pressed`가 `false`가 되고 그 부위만 `true`가 된다. ③ 두 경우 모두 전송값은 각각 `[]`, `[그 부위]`다.
- **AC-P-3** 전송 페이로드의 `pain_areas`는 항상 8개 enum 값의 부분집합이거나 빈 배열이다.
- **AC-P-4** 스텝과 결과 화면 모두에 "의료적 조언이 아니에요" 고지가 보인다.
- **AC-P-5** 전문가 상담 안내 문구가 목록 밖 안내와 함께 노출된다.

기준: **WCAG 2.2 AA**. 아래는 AFC 화면에 대한 구체 적용이다.

### 7.1 포커스

| 항목 | 규칙 |

| 탭 순서 | DOM 순서 = 시각 순서. `tabindex > 0` 금지 |
| S4 탭 순서 | 운동 카드(이름 → `⋯` 메뉴 트리거) → 세트 행 순서대로 → (무게 → 횟수 → RIR → 완료 체크) → 다음 세트 → 다음 운동 → [운동 추가](목록 하단) → [운동 종료]. 열린 메뉴 안 3항목은 Tab 정거장을 늘리지 않고 방향키로 이동한다 |
| S4 완료 세트 | 축약 행은 정거장 **2개**(요약 디스클로저 버튼 → 완료 체크). 펼치면 미완료 행과 같은 순서가 된다 |
| S4 RIR 셰브론 | `tabindex="-1"` — 탭 순서에 없다(§2.4.2) |
| 완료 체크 후 | 포커스를 타이머 팝업으로 이동(§7.2) |
| 팝업 닫힘 후 | 포커스를 **다음 미완료 세트의 첫 입력칸**으로 이동. 다음 세트가 없으면 트리거였던 완료 체크 버튼으로 복귀 |
| 스킵 링크 | 페이지 첫 포커스로 "본문 바로가기" 제공 |

#### 7.2.1 운동 카드 앵커 메뉴와 타이머 시트 포커스 소유권 (D-14·D-17)

운동 카드 `⋯` 메뉴는 모달 시트가 아니라 카드에 앵커된 popover다.

| 항목 | 규칙 |
|---|---|
| 역할 | 컨테이너 `role="menu"`, 각 항목 `role="menuitem"`. 트리거는 `aria-haspopup="menu"`·`aria-expanded` |
| 열기·초기 포커스 | Enter/Space/클릭으로 열고 첫 항목에 포커스. 현재 메뉴 항목은 하나만 `tabindex="0"`, 나머지는 `-1` |
| 이동 | `ArrowDown`/`ArrowUp`으로 순환, `Home`/`End`로 처음/끝. 잠긴 `aria-disabled` 항목도 포커스와 사유 확인을 위해 이동 대상에 남긴다 |
| 닫기 | `Esc`, 외부 클릭, 항목 선택으로 닫는다. 닫힌 뒤 포커스는 **해당 `⋯` 트리거**로 돌아간다 |
| 외부 완료 체크 | 메뉴가 열린 상태에서 완료 체크를 클릭하면 그 첫 클릭은 메뉴만 닫고 소비한다. 완료 처리는 발생하지 않으며, 사용자가 메뉴가 닫힌 뒤 완료 체크를 다시 활성화해야 한다 |
| 잠긴 항목 | [교체]·[삭제] 활성화 시 메뉴는 열린 채 유지하고 요청 0회 + 사유 `role="status"` 낭독. [통증 기록]은 활성 |
| 타이머 시트와 배타 | 완료 체크가 실제 처리되기 전 열린 메뉴가 없어야 한다. 따라서 `role="menu"`와 휴식 타이머 `role="dialog"`가 동시에 열린 DOM 상태는 없다 |
| 복귀 소유권 | 메뉴 닫힘은 트리거 포커스만, 타이머 닫힘은 다음 미완료 세트의 첫 입력(없으면 완료 체크) 포커스만 소유한다. 먼저 닫힌 표면의 지연된 복귀 콜백이 나중 표면의 포커스를 덮어쓰면 안 된다 |

- **AC-MENU-1** 메뉴는 트리거에 앵커되고 `role="menu"`/`menuitem`을 가지며, 메뉴 항목은 정확히 교체·통증 기록·삭제 3개다(건너뛰기 0개).
- **AC-MENU-2** 방향키·Home·End 이동, `Esc`, 외부 클릭 닫기가 동작하고 닫힌 뒤 트리거에 포커스가 돌아온다.
- **AC-MENU-3** 기록이 있으면 교체·삭제가 포커스 가능한 `aria-disabled`이고 통증 기록은 활성이다. 잠긴 액션 활성화의 교체·삭제 요청 수는 0이며 사유가 낭독된다.
- **AC-MENU-4** 메뉴가 열린 채 완료 체크가 처리되거나 타이머 시트가 열리는 경로가 0개다. 메뉴를 닫은 뒤 완료 체크하면 타이머가 포커스를 받고, 타이머를 닫으면 다음 세트 입력으로 이동하며 메뉴 트리거 복귀가 이를 덮어쓰지 않는다.

### 7.3 스크린리더 라벨

| 요소 | 마크업 |
|---|---|
| 세트 완료 체크 | `<button aria-pressed="false" aria-label="벤치프레스 2세트 완료 처리">`. 완료 시 `aria-pressed="true"`, 라벨은 "…완료 취소"로 교체 |
| 완료 세트 축약 행 | `<button aria-expanded="false" aria-label="벤치프레스 3세트 기록, 62.5킬로그램 9회, RIR 2, 완료. 수정하려면 누르세요">`(§2.4.3). 축약 상태에서도 기록값 전부를 읽는다 |
| 세트 행 상태 | 완료 표시는 아이콘+텍스트("완료"). 아이콘 단독일 경우 `aria-label="완료됨"` |
| 무게 입력 | `<input aria-label="벤치프레스 2세트 무게, 킬로그램" inputmode="decimal">` |
| 횟수 입력 | `aria-label="벤치프레스 2세트 횟수, 회"` `inputmode="numeric"` |
| 시간 입력 | `aria-label="플랭크 1세트 유지 시간, 초"` `inputmode="numeric"` |
| RIR 입력 | **F1-1 2차 개정: 단일 필드**(입력칸 + `tabindex="-1"` 셰브론 → 시트). `aria-label="벤치프레스 2세트 RIR, 남은 반복 수. 0에서 6, 비워 두면 모름"` + `aria-describedby`로 "목표 2" 연결. 라디오 그룹·`select` 아님(§2.4.2) |
| RIR 셰브론 | `aria-label="벤치프레스 2세트 RIR 고르기"` `aria-haspopup="dialog"` `aria-expanded` |
| 무게 미정 배지 | 카드 헤더 1회. `aria-label="추천 무게 없음, 직접 입력"` |
| 자체중량 배지 | 카드 헤더 1회. `aria-label="자체중량 운동, 무게 입력 없음"` |
| 운동 메뉴 트리거 | `<button aria-label="벤치프레스 메뉴" aria-haspopup="menu" aria-expanded="false">` |
| 운동 메뉴 항목 | 교체·통증 기록·삭제 3개 `role="menuitem"`. 기록이 있으면 교체·삭제에 `aria-disabled="true"` + `aria-describedby`로 사유를 연결하고, 통증 기록은 활성(§2.4.4·§7.2.1) |
| 타이머 팝업 | `role="dialog" aria-label="휴식 타이머"` |
| 카운트다운 숫자 | `role="timer" aria-atomic="true"`. **`aria-live`는 `off`** (매초 낭독 금지) |
| 진행 바 | `aria-hidden="true"`(카운트다운과 중복 정보). 단독 사용 시에만 `role="progressbar" aria-valuemin/max/now` + `aria-valuetext="1분 30초 남음"` |
| +시간 버튼 | `aria-label="휴식 30초 추가"`. 상한 도달 시 `aria-disabled="true"`(DOM에서 제거하거나 `disabled`로 포커스를 뺏지 않는다) |
| 오프라인 배지 | `role="status"`, 텍스트 "오프라인" |

### 7.4 `aria-live` 사용처

| 위치 | 설정 | 낭독 내용 |
|---|---|---|
| 타이머 마일스톤 | 시각적으로 숨긴 `aria-live="polite"` 영역 | 남은 시간 60초·30초·10초·0초 시점에만 "1분 남음" / "30초 남음" / "10초 남음" / "휴식 완료". **매초 낭독 금지** |
| 시간 가산 결과 | 같은 polite 영역(500ms 디바운스 — 연타 시 마지막 값만) | "남은 시간 2분 30초" |
| 상한 도달 | 같은 polite 영역 | "휴식은 최대 10분까지 늘릴 수 있어요" |
| 세트 완료 토스트 | `role="status"`(= polite) | "2세트 완료" |
| 저장·동기화 상태 | `role="status"` | "저장했어요" / "오프라인, 기록은 저장됐어요" |
| 오류 배너 | `role="alert"`(= assertive) | 오류 문구 그대로 |
| 목록 갱신(F5 추가/삭제) | `role="status"` | "{운동 이름}을 루틴에 추가했어요" / "{운동 이름}을 루틴에서 뺐어요" |
| 교체·삭제 잠금 사유(§2.4.4) | `role="status"` (잠긴 메뉴 항목을 활성화할 때 1회) | "기록이 있는 운동이라 빼거나 바꿀 수 없어요. 완료 체크를 해제해 주세요." |

> assertive는 **오류에만** 쓴다. 그 외 전부 polite.

### 7.5 키보드만으로 핵심 루프 완주

다음 경로가 마우스·터치 없이 완주 가능해야 한다.

```
대시보드 [운동 시작] → 세트1 무게 입력 → Tab → 횟수 입력 → Tab → RIR 입력(숫자 타이핑 또는 ↑/↓) →
Tab → 완료 체크(Enter/Space) → 타이머 팝업 자동 포커스 → (Tab으로 +30초) →
Enter로 [휴식 종료] → 다음 세트 입력칸에 포커스 → … → [운동 종료] → 확인 시트 → 종료
```

| 항목 | 규칙 |
|---|---|
| RIR 단일 필드 | 숫자 타이핑(0~6 밖은 **거부** — clamp 아님, 값이 바뀌지 않는다) / `↑`·`↓`로 ±1(0·6에서 멈춤) / `Backspace`로 모름 / `Alt+↓`로 고르기 시트. 셰브론은 `tabindex="-1"`이라 Tab으로 지나가지 않는다(§2.4.2) |
| 완료 세트 축약 행 | `Enter`/`Space`로 펼치고 접는다(`aria-expanded` 갱신). 펼치면 포커스는 첫 입력칸으로 이동 |
| 세트 스테퍼 | ↑/↓로 증감 |
| 부위 탭(F5) | ←/→로 탭 이동(`role="tablist"` 표준 패턴) |
| 통증 부위 칩(F0) | Tab으로 순회, Space로 토글(`role="checkbox"` 또는 `aria-pressed` 버튼) |
| 모든 커스텀 컨트롤 | `div` + `onClick` 금지. 네이티브 요소 우선 |

- **AC-A-1** 위 경로를 키보드만으로 완주할 수 있다(마우스 이벤트 0회).
- **AC-A-2** 포커스가 보이지 않는 구간이 0개다.
- **AC-A-3** 타이머가 매초 낭독되지 않고, 마일스톤 4회만 낭독된다.

| 항목 | 기준 |

## 8. 한 손 조작 원칙

전제: 세로 모드 한 손 파지, 기준 화면 폭 360~430px. 화면을 세로 3구역으로 나눈다.

| 구역 | 범위(세로) | 용도 |
|---|---|---|
| **상단** | 0~30% | 읽기 전용 정보(운동 이름, 목표, 근거 배지, 오프라인 배지). 액션 배치 금지(단, 뒤로가기 제외) |
| **중단** | 30~65% | 값 입력(무게·횟수·RIR). 스크롤 영역 |
| **하단(엄지 반경)** | 65~100% | **주 액션**: 세트 완료 체크, 타이머 [휴식 종료]/[다음 세트], +시간 버튼, 확인 시트 버튼 |

| 규칙 | 내용 |
|---|---|
| 세트 완료 체크 위치 | 세트 행의 **오른쪽 끝**(엄지 자연 궤적). 행 높이 56px 이상 |
| 타이머 팝업 | 화면 **하단에서 올라오는 시트**로 띄운다. 큰 카운트다운은 시트 상단, 조작 버튼은 시트 하단 |
| +시간 버튼 4개 | 한 줄 4등분, 각 44px 이상. [휴식 종료] 바로 위 |

| 스크롤 | 타이머 시트가 떠 있는 동안 배경 스크롤 잠금(오조작으로 값이 어긋나지 않게) |

## 11. M-4′ 집계 화면 상태 계약

- 온라인 기록/e1RM/추천은 서버가 `no_history|early|ready`로 게이트한 응답을 그대로 렌더한다.
- 오프라인 read-through는 마지막 서버 snapshot의 gate와 nullable 값을 그대로 보존하며 `stale`과
  `synced_at`을 함께 표시한다. 미전송 outbox를 서버 집계에 합쳐 권위값처럼 보이지 않는다.
- 향후 별도 provisional 집계를 추가할 때만 `packages/shared/display-gate.ts`를 사용하고, 서버 응답이
  도착하면 provisional 전체를 서버 snapshot으로 교체한다(D-39·D-52).
- `early`(종목별 완료 세션 1~2회)는 날짜 점과 “N회 기록됨. 세 세션부터 추이를 보여드립니다.”를
  표시하되 e1RM 숫자·연결선·다음 추천·추천 근거를 DOM에 두지 않는다.
  > **V2 예정(ADR-70) — 현재 코드는 아직 V1.** V2의 `early`는 e1RM 숫자·연결선·`confidence`만 DOM에서 빼고
  > **다음 추천과 추천 근거는 첫 세션부터 DOM에 둔다.** external 첫 세션은 무게만 비고 target reps와
  > `LOAD_CALIBRATION_NEEDED` 근거는 그대로 표시한다 — load 값만 미준비라는 뜻이다.
  > `docs/PROGRAM_V2_CONTRACT.md` §1·§1.1. 실제 교체는 V2-GATE-01에서 코드와 함께 한다.
- 주간 프로그램의 미래 lazy 주차는 `예정`으로 표시하고 session ID나 저장된 세션인 것처럼 행동하지 않는다.
- 계획 충돌·볼륨 범위 이탈은 읽기 전용 안내다. 일정 재배치 CTA를 만들지 않는다(ADR-24/D-42).
- 기록 상세는 계획 대비 실제를 읽기 전용으로 보여준다. 과거 날짜 수행값을 수정·추가하는 UI는 만들지 않는다.
