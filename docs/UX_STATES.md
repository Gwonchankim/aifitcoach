# AFC 인터랙션·상태·접근성·마이크로카피 스펙 (STEP 5)

> 대상: STEP 5 프론트 구현(`apps/web`). 이 문서는 `docs/FEATURES_UX.md`(F0~F8)를 **화면 상태·문구 수준으로 해석·보강**한 것이다.
> 기능의 진실의 원천은 `FEATURES_UX.md`, 계약의 진실의 원천은 `docs/specs/openapi.yaml`이다. 충돌하면 그쪽이 이긴다.
> 이 문서는 **새 기능을 정의하지 않는다.** FEATURES_UX에 없는 동작은 추가하지 않았고, 스펙이 침묵하는 곳은 `[확인 필요]`로 표시했다.
>
> 표기 규칙
> - `[해석]` = FEATURES_UX가 두 갈래 이상으로 읽히는 곳을 근거와 함께 한쪽으로 확정한 것. 뒤집을 수 있다.
> - `[확인 필요]` = 임의로 정하면 안 되는 공백. **frontend는 이 항목을 구현으로 결정하지 말고 tech-lead에 올린다.**
> - `AC-xx` = 수용 기준(QA가 그대로 검증한다).
> - 시각 토큰(색·간격·타이포 실값)은 이 문서 밖이다 → design과 협의.

## 1. 공통 규칙

### 1.1 상태 5종 정의

| 상태 | 정의(판별 기준) |
|---|---|
| **빈(empty)** | 요청은 성공했으나 보여줄 데이터가 0건이다. 또는 선행 데이터(프로그램)가 없다. |
| **로딩(loading)** | 첫 조회 중이라 화면을 구성할 데이터가 아직 없다. 재조회(refetch)는 로딩이 아니라 **갱신 중**으로 다룬다. |
| **에러(error)** | 서버가 4xx/5xx를 반환했다. 상태코드별 처리는 §3. |
| **오프라인(offline)** | `navigator.onLine === false` 이거나 요청이 네트워크 레벨에서 실패했다. |
| **부분 수행(partial)** | 오늘 세션의 계획 세트 중 일부만 완료 체크됐다(F7). 에러가 아니라 **정상 상태**다. |

### 1.2 표현 규칙

| 규칙 | 값 | 근거 |
|---|---|---|
| 로딩 인디케이터 지연 | 200ms 미만 응답에는 아무것도 띄우지 않는다(깜빡임 방지) | — |
| 첫 로딩 | 스켈레톤(레이아웃 자리 유지). 스피너는 버튼 내부 등 국소 영역에만 | — |
| 갱신 중(refetch) | 기존 데이터를 계속 보여주고 상단에 가는 진행 표시만. 화면을 비우지 않는다 | 한손 로깅 중 화면이 사라지면 안 됨 |
| 되돌릴 수 있는 알림 | 하단 토스트(4초, 스와이프/버튼으로 닫기 가능) | — |
| 되돌릴 수 없는 알림·차단성 오류 | 해당 영역 인라인 배너(자동 소멸 금지) | 토스트는 스크린리더/시선 밖에서 놓치기 쉬움 |
| 파괴적 확인 | 시트(bottom sheet). 기본 포커스는 **취소** | 오조작 방지 |
| 재시도 | 사용자가 누르는 명시적 [다시 시도] 버튼. 자동 무한 재시도 금지 | — |

### 1.3 마이크로카피 톤

- **존댓말 + 간결체**(`~해요`, `~해 주세요`). 최대 2문장. 1문장 = 원인, 1문장 = 다음 행동.
- 버튼은 **동사 중심 2~5자**: `다시 시도`, `루틴 보기`, `운동 종료`, `휴식 종료`, `계획 만들기`.
- **금지어**: 에러, 실패, 오류 코드, 서버, API, 동기화(내부 용어), 세션(내부 용어 → "오늘 운동"), 필드명(`sets`, `pain_areas` 등), 영문 상태코드, 스택/예외 메시지.
- **숫자·단위**: `62.5kg`, `9회`, `40초`, `1분 30초`. 무게는 소수점 1자리까지, 정수면 소수점 생략(`60kg`).
- **의료 표현 금지**: 진단·치료·완치·호전 등의 단정 금지. 통증 관련 문구에는 항상 "일반적인 안내이며 의료적 조언이 아니에요"를 함께 둔다(`docs/SAFETY_PAIN_MAPPING.md` 규칙 6).
- **과장 금지**: "완벽한", "최적의", "AI가 분석한" 같은 수식 대신 근거를 그대로 말한다(예: "지난번 3세트 모두 목표 상단을 채웠어요").

### 1.4 데이터 의존성(STEP 5 착수 전 확인)

| 화면 요소 | 필요한 것 | 현재 상태 |

| 운동 이름(한국어) 표시 | `GET /v1/exercises` (`Exercise.name_ko`, `metric`) | **구현됨**(STEP 5). 커서 페이징 — 마지막 페이지는 `next_cursor` 키가 생략된다 |
| F5 추가/교체 후보 목록 | `GET /v1/exercises` + 클라이언트 부위 필터 | 계약에 `region` 쿼리·필드가 없어 30종 전량을 받아 `primary_muscles`로 분류한다 |
| F8 대시보드 | `GET /v1/dashboard` | **구현됨**(STEP 5). `weekly_completion_rate`는 0~1 비율 |

## 2. 화면별 상태 매트릭스

화면 ID: **S1** 온보딩(F0) / **S2** 프로그램 확인 / **S3** 대시보드(F8) / **S4** 데일리 루틴·로깅(F1~F5, F7) / **S5** 운동 요약(F6).

### 2.1 S1 온보딩 (F0)

수집 항목(FEATURES_UX F0): 프로필(성별·출생연도·키·체중), 목표 3종, 주당 일수, 1회 운동 시간, 보유 장비, 통증 부위.
**단계 구성 = 6스텝**(1 프로필 / 2 목표 / 3 주당 일수 / 4 1회 시간 / 5 장비 / 6 통증 부위) `[해석]` — FEATURES_UX는 항목만 나열하고 단계 수를 정하지 않는다. 한 화면 1결정이 한손 조작·이탈률에 유리하다.

| 상태 | 조건 | 화면 | 마이크로카피 | 다음 행동 |
|---|---|---|---|---|
| 진행 | 기본 | 상단 진행 표시(`3/6`), 하단 [다음]. 각 스텝 기본값 선택됨 | 스텝 제목은 질문형: "어떤 목표로 운동하세요?" | [다음] / [이전] |
| 빈 | 해당 없음(모든 스텝에 기본값 존재) | — | — | — |
| 로딩 | `POST /programs/generate` 요청 중 | 전체 화면 진행 상태. **뒤로 가기 차단**(중복 생성 방지) | "운동 계획을 만들고 있어요. 잠시만요." | 없음(취소 불가) `[해석]` |
| 에러 | 400/500 | 마지막 스텝에 인라인 배너로 복귀, 입력값 보존 | §3 표 | [다시 시도] |
| 오프라인 | 제출 시 오프라인 | 입력값을 로컬에 보존하고 제출만 막는다 | "인터넷이 연결되면 계획을 만들어 드릴게요. 입력한 내용은 저장해 뒀어요." | [다시 시도] |
| 부분 수행 | 중도 이탈 후 재진입 | 마지막으로 완료한 스텝부터 재개 | "이어서 진행할게요." | [이어하기] / [처음부터] |

- **AC-S1-1** 모든 스텝은 뒤로 가도 입력값이 유지된다(브라우저 뒤로가기 포함).
- **AC-S1-2** 제출 중 [다음]·뒤로가기 재입력으로 `generate`가 2번 호출되지 않는다.
- **AC-S1-3** 통증 부위 스텝은 §6 규칙을 그대로 만족한다.
- **AC-S1-4** 마지막 스텝의 CTA는 `계획 만들기`(`제출`·`완료` 아님).

### 2.2 S2 프로그램 확인 (F0 후속)

`POST /programs/generate` 201 응답 또는 `GET /programs/current` 200을 렌더한다.

**'왜 이 루틴' 근거 문구는 응답 필드로 조립한다** `[해석]` — `Program`에는 자유 텍스트 근거 필드가 없다(`goal`, `split_type`, `rules_version`, `excluded_exercises`, `sessions`만). 없는 필드를 요구하는 대신 클라이언트 템플릿으로 만든다:

```
{목표라벨} 목표에 맞춰 주 {days_per_week}일 {split_type라벨} 방식으로 짰어요.
하루 {minutes_per_day}분 기준으로 운동 {n}개를 배치했어요.
```
- 목표 라벨: `diet`→다이어트 / `hypertrophy`→근비대 / `strength`→스트렝스
- 분할 라벨: `full_body`→전신 / `upper_lower`→상·하체 분할 / `ppl`→밀기·당기기·하체 분할. **목록 밖 값이면 분할 문장을 통째로 생략**(원문 노출 금지).

| 상태 | 조건 | 화면 | 마이크로카피 |
|---|---|---|---|
| 정상 | `sessions.length > 0` | 요일별 카드(요일·focus·운동 수) + '왜 이 루틴' + 제외 운동 섹션 | 위 템플릿 |
| 빈 ① | `excluded_exercises = []` | 제외 섹션 자체를 **표시하지 않는다**(빈 카드 금지) | — |
| 빈 ② | 특정 요일 `exercises = []` (안전 제외로 축소된 프로그램) | 해당 요일 카드에 안내 | "선택하신 통증 부위 때문에 이 날 추천할 수 있는 운동이 없어요. 통증이 나아지면 계획을 다시 만들 수 있어요. 일반적인 안내이며 의료적 조언이 아니에요." + [전문가 상담 안내] |
| 빈 ③ | `GET /programs/current` 404 | 온보딩 유도 | "아직 운동 계획이 없어요." / [계획 만들기] |
| 로딩 | 조회 중 | 카드 3개 스켈레톤 | — |
| 에러 | 500 | 전체 영역 인라인 배너 | §3 |
| 오프라인 | 캐시 있음 | 캐시 렌더 + 상단 오프라인 배지 | "오프라인이에요. 마지막으로 받아온 계획을 보고 있어요." |
| 오프라인 | 캐시 없음 | 빈 화면 + 배너 | "인터넷이 연결되면 계획을 보여드릴게요." / [다시 시도] |

**제외 운동 섹션 표기**(`excluded_exercises[]`)

| 요소 | 규칙 |
|---|---|
| 제목 | "안전을 위해 뺀 운동 {n}개" |
| 항목 | `{운동 이름}` + 사유 배지 `{통증부위 라벨}` |
| 사유 문구 | 서버 `reason`을 그대로 노출한다(이미 한국어·"의료적 조언이 아니다" 포함). `movement_pattern`·`exercise_id` 원문은 노출 금지 |
| 하단 고지 | "일반적인 회피 가이드이며 의료적 조언이 아니에요. 통증이 계속되거나 심해지면 전문가와 상담해 주세요." |

- **AC-S2-1** 화면 어디에도 `exercise_id`·`movement_pattern`·`rules_version` 원문이 노출되지 않는다.
- **AC-S2-2** `excluded_exercises`가 1건 이상이면 제외 섹션이 항상 보인다(접힘 기본값이어도 존재해야 한다).

### 2.3 S3 대시보드 (F8)

`GET /v1/dashboard` → `DashboardSummary`.

| `today.status` | 주 카드 | 마이크로카피 | 주 액션 |
|---|---|---|---|
| `workout` | 오늘 루틴 요약(`routine_summary.exercise_count`, `focus`) | "오늘은 {focus라벨} 운동 {n}개예요." | [운동 시작] |
| `rest` | 휴식 안내 | "오늘은 휴식이에요. 잘 쉬는 것도 훈련이에요." | 없음(부 액션: [내일 루틴 보기]) |
| `done` | 오늘 기록 요약(`done_summary`) | "오늘 운동 완료! 총 {total_volume}kg · {sets_completed}세트" | [기록 보기] |

| 상태 | 조건 | 화면 | 마이크로카피 |
|---|---|---|---|
| 빈 ① | 프로그램 없음(선행 404) | 온보딩 카드 하나만 | "운동 계획을 먼저 만들어 주세요." / [계획 만들기] |
| 빈 ② | `streak_days = 0` | 스트릭 칩을 숨기지 않고 0으로 표시 | "연속 0일 — 오늘부터 시작해요" |
| 빈 ③ | `weekly_completion_rate = 0`이고 이번 주 계획도 0 | 완료율 카드 대신 안내 | "이번 주 기록이 아직 없어요." |
| 빈 ④ | e1RM 추세 데이터 2점 미만 | 그래프 대신 안내(빈 축 금지) | "기록이 2회 이상 쌓이면 변화를 보여드릴게요." |
| 빈 ⑤ | `tomorrow.status = rest` | 내일 카드 | "내일은 휴식이에요." |
| 로딩 | 첫 조회 | 카드 스켈레톤(오늘/내일/지표 3개) | — |
| 에러 | 500 | 카드 단위로 실패 격리 — 오늘 카드가 실패해도 나머지는 렌더 | "지금은 불러오지 못했어요." / [다시 시도] |
| 오프라인 | 캐시 있음 | 캐시 + 배지 + **갱신 시각** 표기 | "오프라인 · {HH:mm} 기준" |
| 오프라인 | 캐시 없음 | 전체 빈 상태 | "인터넷이 연결되면 요약을 보여드릴게요." |
| 부분 수행 | 오늘 일부만 완료했고 아직 운동 종료 전(`today.status = workout`이지만 로컬에 완료 세트 있음) | 오늘 카드에 진행 배지 | "진행 중 · {완료}/{전체} 세트" / [이어서 하기] |

- **AC-S3-1** `today.status`가 `done`일 때 [운동 시작] CTA가 보이지 않는다.
- **AC-S3-2** 지표 카드 하나가 실패해도 다른 카드는 정상 렌더된다(전체 화면 에러 금지).
- **AC-S3-3** 오프라인 배지가 있을 때 표시 중인 수치의 기준 시각이 함께 보인다.

### 2.4 S4 데일리 루틴 · 로깅 (F1~F5, F7)

`GET /v1/sessions/{id}` → `Session.planned_sets[]`. 운동 단위로 그룹핑하고(`exercise_id` + `order_index` 순), 각 운동 카드 안에 세트 행을 둔다.

|---|---|

- **AC-S4-2** 오프라인에서 세트 3개를 체크하고 앱을 새로고침해도 체크 상태가 남아 있다.

- **AC-S4-5** 통증 시트에는 항상 "의료적 조언이 아니에요" 고지가 함께 보인다.

## 3. 에러 처리 매핑

### 3.0 원칙

1. **서버 `error.message`를 사용자에게 그대로 노출하지 않는다.** STEP 4 메시지는 개발자용 해라체이고(`"세션을 찾을 수 없다."`) 일부는 식별자를 포함한다(`운동을 찾을 수 없다: e_xxx`). 화면 문구는 **아래 표의 문구를 쓴다**.
2. `error.code`(`VALIDATION_ERROR`/`NOT_FOUND`/`CONFLICT`/`INTERNAL_ERROR`/`NOT_IMPLEMENTED`)는 **로그·계측용**이다. 화면에 렌더하지 않는다.
3. **예방 > 복구.** 400/409의 대부분은 UI가 애초에 잘못된 요청을 못 만들게 하면 발생하지 않는다(§3.3).
4. 오류 문구는 `원인 + 다음 행동` 2문장을 넘기지 않는다.

### 3.1 상태코드 → 기본 문구

| 코드 | 서버 `code` | 기본 문구 | 표시 | 기본 액션 |
|---|---|---|---|---|
| 400 | `VALIDATION_ERROR` | "입력한 값을 다시 확인해 주세요." | 해당 입력칸 인라인 | 해당 칸으로 포커스 이동 |
| 404 | `NOT_FOUND` | "이 정보를 찾을 수 없어요." | 영역 배너 | [다시 불러오기] |
| 409 | `CONFLICT` | "다른 곳에서 먼저 바뀐 것 같아요. 최신 상태로 다시 불러올게요." | 토스트 + 자동 재조회 | 자동 재조회 1회 |
| 500 | `INTERNAL_ERROR` | "잠시 문제가 있었어요. 다시 시도해 주세요." | 영역 배너 | [다시 시도] |
| 501 | `NOT_IMPLEMENTED` | "이 기능은 아직 준비 중이에요." | 영역 배너 | 없음(개발 단계 한정) |
| 네트워크 실패/타임아웃 | — | "인터넷 연결이 불안정해요. 연결되면 자동으로 이어서 진행할게요." | 상단 배지 | 자동(연결 복구 시) |

> **409는 코드만으로 원인을 구분할 수 없다.** 서버는 세 경우 모두 `{ code: "CONFLICT" }`를 준다(메시지만 다름). 프론트는 **한국어 메시지 문자열 매칭으로 분기하지 않는다**(취약). 대신 **액션 컨텍스트**로 문구를 고르고(§3.3에서 대부분 사전 차단), 구분이 불가능한 잔여 409는 §3.1 기본 409 문구 + 자동 재조회로 처리한다.
> 제안(계약 변경이라 임의 적용하지 않음, §10 C-3): `error.details.reason ∈ {session_completed, duplicate_exercise, has_performed_sets}`.

### 3.3 발생 자체를 막는 UI 규칙(예방)

| 잠재 오류 | 예방 규칙 |
|---|---|
| 400 `pain_areas` | 자유 입력 없음. 8개 칩만(§6). 전송값은 enum 상수 배열에서만 나온다 |
| 400 `sets` 범위 | 세트 스테퍼 `min=1, max=10`. 상·하한에서 버튼 비활성 + "1~10 사이로 정할 수 있어요" |
| 400 없는 `exercise_id` | 후보 목록은 항상 `GET /exercises` 응답에서만 만든다. 직접 입력 없음 |
| 400 통증 점수 | 0~10 칩/슬라이더만. 자유 입력 없음 |
| 409 중복 종목 | 추가/교체 팝업에서 **오늘 루틴에 이미 있는 종목은 비활성 + "이미 루틴에 있어요" 배지**(세션 응답의 `planned_sets[].exercise_id`로 판정, 추가 계약 불필요) |
| 409 완료된 세션 | `status = completed`면 편집 UI를 렌더하지 않는다(AC-S4-3) |
| 409 수행 기록 있음 | 완료 체크된 세트가 1개 이상인 운동은 [삭제]·[교체] 비활성 + "기록이 있어 바꿀 수 없어요"(AC-S4-4) |
| 중복 제출 | 제출 중 버튼 비활성 + 낙관적 상태 잠금 |

## 4. 휴식 타이머 상세 (F2 / F3 / F4)

서버 저장이 없는 **순수 클라이언트 상태**다(FEATURES_UX "데이터·계약 영향"). 추천 휴식값 = 그 세트의 `planned_set.rest_sec`.

### 4.1 상태 머신

```
closed ──(세트 완료 체크)──> running ──(remaining <= 0)──> finished
   ^                            │                              │
   └──── [휴식 종료] / Esc ──────┴───── [닫기] / [다음 세트] ────┘
```
- **일시정지 상태는 없다**(F2~F4에 정지 기능이 없다 — 임의 추가 금지).
- 여러 타이머가 동시에 뜨지 않는다. `running` 중 다른 세트를 체크하면 **새 세트 기준으로 타이머를 교체**한다 `[해석]`.

### 4.2 시간 계산(단일 진실값)

| 변수 | 정의 |
|---|---|
| `totalSec` | 현재 총 휴식 시간. 시작값 = `rest_sec`. F3 가산 시 갱신 |
| `endsAt` | 절대 종료 시각(epoch ms). 시작 시 `Date.now() + totalSec*1000` |
| `remainingSec` | `Math.max(0, Math.ceil((endsAt - Date.now()) / 1000))` |
| `elapsedSec` | `totalSec - remainingSec` |

- **누적 감산 금지**: `setInterval`마다 `remaining -= 1` 하지 않는다(드리프트·백그라운드 스로틀로 어긋난다). **항상 `endsAt`에서 다시 계산**한다.
- 틱 주기 200ms. 화면 텍스트는 `remainingSec`가 바뀔 때만 갱신.

### 4.3 표기

| 항목 | 규칙 | 예 |
|---|---|---|
| 카운트다운 | `분:초`, 초는 2자리 zero-pad, 분은 pad 없음 | `1:30`, `0:07`, `10:00` |
| 60초 미만 | 그대로 `0:45`(초만 크게 쓰지 않는다 — 자릿수 흔들림 방지) | `0:45` |
| 종료 | `0:00` + 상태 라벨 "휴식 완료" | — |
| 숫자 폰트 | tabular-nums 고정폭(값이 바뀌어도 폭이 흔들리지 않게) | — |
| 보조 라벨 | 상단에 "{운동 이름} {n}세트 후 휴식" | — |

### 4.4 진행 바

| 항목 | 규칙 |
|---|---|
| 값 | `percent = remainingSec / totalSec * 100` (100% → 0%) |
| 갱신 | 틱(200ms)마다 폭 갱신. CSS `transition: width 200ms linear`로 부드럽게 |
| `prefers-reduced-motion: reduce` | transition 제거, 1초 간격 계단식 갱신 |
| 시간 가산 시 | `totalSec` 재계산 후 **percent가 즉시 위로 점프**한다(F3: "새 총시간 기준으로 갱신"). 점프는 애니메이션 없이 즉시 반영 |
| 0 도달 | 폭 0%. 바를 숨기지 않는다(위치 흔들림 방지) |
| 접근성 | §7.3 — 바는 카운트다운 텍스트와 중복 정보이므로 `aria-hidden="true"` |

### 4.5 시간 증가 (F3)

버튼 4개: `+5초` `+10초` `+30초` `+1분`.

| 항목 | 규칙 |
|---|---|
| 동작 | 탭 즉시 `remainingSec`에 가산. 디바운스·쓰로틀 **없음**(연타가 그대로 누적, 예: +30초 3연타 = +90초) |
| 구현식 | `elapsed = totalSec - remainingSec` → `remainingNew = min(600, remainingSec + delta)` → `totalSec = elapsed + remainingNew` → `endsAt = Date.now() + remainingNew*1000` |
| 상한 | **남은 시간 기준 10분(600초)** `[해석]` — FEATURES_UX는 "합리적 상한(예: 10분)"만 정한다. 사용자가 보는 값이 남은 시간이므로 남은 시간에 건다 |
| 상한 부분 적용 | 상한에 걸리면 **가능한 만큼만 더한다**(예: 남은 580초 + 60초 → 600초). 요청을 통째로 무시하지 않는다 |
| 상한 도달 피드백 | ① 4개 버튼 `aria-disabled="true"` + 흐리게(포커스는 유지), ② 토스트 1회(중복 억제 3초): "휴식은 최대 10분까지 늘릴 수 있어요.", ③ 남은 시간이 600초 미만으로 내려가면 자동 재활성 |
| 눌러도 되는 시점 | `running` 상태에서만. `finished`에서는 4개 버튼을 숨긴다 `[해석]` |
| 시각 피드백 | 탭마다 카운트다운 숫자에 짧은 강조(120ms). reduced-motion이면 생략 |

### 4.6 휴식 종료 (F4)

| 항목 | 규칙 |
|---|---|
| 위치 | 팝업 **하단 전폭 버튼**(엄지 반경, §8) |
| 라벨 | `휴식 종료` |
| 동작 | 확인 없이 **즉시** 타이머 종료 + 팝업 닫기 + 다음 미완료 세트 행으로 포커스·스크롤 이동 |
| 키보드 | `Esc` = [휴식 종료]와 동일 `[해석]` |
| 배경 탭 | 배경(딤) 탭으로도 닫는다. 동작은 [휴식 종료]와 동일 |

### 4.7 0초 도달

| 항목 | 규칙 |
|---|---|
| 팝업 | **자동으로 닫지 않고** `finished` 상태로 전환한다 `[해석]` — FEATURES_UX는 "자동 닫힘 **또는** '다음 세트' 준비 상태" 두 갈래를 준다. 알림이 기본 off라 자동으로 닫으면 사용자가 종료 사실을 놓친다 |
| 화면 | `0:00` + "휴식 완료" + 하단 버튼이 [다음 세트]로 바뀜. +시간 버튼 숨김 |
| [다음 세트] | 팝업 닫고 다음 미완료 세트 입력칸으로 포커스 이동 |
| 알림 | **기본 off**(FEATURES_UX 안전 절). 설정에서 켠 경우에만 소리·진동 1회 |
| 알림 조건 | 문서가 보이는 상태(`visibilityState === "visible"`)일 때만 재생한다. 백그라운드였다면 재생하지 않고 복귀 시 `finished` 화면만 보여준다 (브라우저 자동재생·진동 제약) |
| 초과 시간 | 0:00에서 멈춘다. 경과 시간 카운트업은 하지 않는다(스펙에 없음) |

### 4.8 백그라운드 / 탭 전환 복귀 보정

| 이벤트 | 처리 |
|---|---|
| `visibilitychange` → visible | `endsAt`으로 `remainingSec` 재계산 → 0 이하면 즉시 `finished`로 전환 |
| `focus`, `pageshow`(bfcache 복귀 포함) | 위와 동일 재계산 |
| 백그라운드 동안 | 타이머 상태는 메모리 + **`endsAt`을 세션 스토리지에 보존**. 새로고침 후 복귀해도 남은 시간이 이어진다 |
| 앱 완전 종료 후 재진입 | `endsAt`이 과거면 타이머를 복원하지 않고 `closed`로 시작한다(유령 타이머 방지) |
| 시계 되돌림 등 이상값 | `remainingSec > totalSec`이면 `totalSec`으로 clamp |

### 4.9 수용 기준

- **AC-T-1** `1:30`처럼 분:초로 표기되고, 초는 항상 2자리다.
- **AC-T-2** 진행 바가 시작 100%에서 종료 0%까지 단조 감소한다(시간 가산 시점 제외).
- **AC-T-3** `+30초`를 1초 안에 3번 연타하면 남은 시간이 정확히 90초 늘어난다.
- **AC-T-4** 남은 시간 590초에서 `+1분`을 누르면 600초가 되고, 상한 안내가 1회 뜨며, 4개 버튼이 비활성된다.
- **AC-T-5** [휴식 종료]는 확인 단계 없이 한 번의 탭으로 즉시 닫힌다.
- **AC-T-6** 타이머 실행 중 탭을 60초 동안 백그라운드로 두었다 돌아오면 남은 시간이 정확히 60초 줄어 있다.
- **AC-T-7** 백그라운드에서 0초가 지난 뒤 복귀하면 `finished` 화면이 보인다(카운트다운이 음수로 가지 않는다).
- **AC-T-8** 알림 설정이 off(기본)이면 0초에 소리·진동이 발생하지 않는다.
- **AC-T-9** 타이머가 떠 있는 동안에도 뒤 배경의 기록 값은 소실되지 않는다.

## 5. 엣지 케이스 렌더링 규칙 (중요)

### 5.1 판별 순서

세트 행을 그리기 전에 **반드시 이 순서로** 분기한다. `recommended_weight` 값만 보고 그리면 안 된다.

```
1) metric === "time"                      → 시간 종목   (§5.4)
2) recommended_weight === null            → 자체중량    (§5.3)
3) recommended_weight === 0 && reason_code === "BASELINE" → 무게 미정 (§5.2)
4) 그 외                                   → 일반(가중·반복)
```
- `metric`의 1차 출처는 카탈로그 `Exercise.metric`이다. 카탈로그를 아직 못 받았다면 `target_time_low_sec != null`을 폴백 판별로 쓴다.
- `PlannedSet`의 반복 축(`target_reps_*`, `recommended_reps`, `target_rir`)은 nullable이다. **null인 축은 렌더하지 않는다**(`-`, `0`, `null` 출력 금지).

### 5.2 `BASELINE` 첫 세션 — `weight: 0` (0kg 표시 금지)

> 추천 엔진은 기록이 없을 때 `weight = 0` + `reason_code = "BASELINE"`을 반환한다. **이건 "0kg을 들어라"가 아니라 "무게 미정"이다**(PROGRESS STEP 3 계약 메모).

| 요소 | 규칙 |
|---|---|
| 무게 표시 | `무게 미정` (배지 형태). **`0kg`·`0`·`-` 절대 금지** |
| 무게 입력칸 | 빈 칸 + placeholder `무게 입력`. **프리필하지 않는다** |
| 보조 문구(운동 카드 1회) | "첫 세션이라 추천 무게가 아직 없어요. 가볍게 워밍업하면서 오늘의 무게를 정해 보세요." |
| 완료 체크 | 무게가 비어 있으면 체크를 막고 입력칸으로 포커스 이동 + "무게를 입력해 주세요." |
| 반복 | `recommended_reps`/`target_reps_low~high`는 정상 표시 |
| RIR | 정상적으로 묻는다 |
| 2세트 이후 | 같은 운동의 앞 세트에 입력한 무게를 다음 세트 입력칸에 프리필한다 `[해석]`(같은 세션 내 반복 입력을 줄이기 위함) |

- **AC-E-1** `reason_code = BASELINE`인 세트 어디에도 문자열 `0kg`이 렌더되지 않는다.
- **AC-E-2** 무게가 비어 있는 BASELINE 세트는 완료 체크가 되지 않는다.

### 5.3 맨몸(자체중량) 종목 — `recommended_weight: null`

> 엔진은 맨몸 종목에 부하를 처방하지 않는다(`weight = null`). 진행은 반복으로 한다(`REPS_UP_BODYWEIGHT` 등).

| 요소 | 규칙 |
|---|---|
| 무게 표시 | `자체중량` (배지). `0kg`·빈칸 금지 |
| 무게 입력칸 | **표시하지 않는다.** 추가 부하(웨이트 벨트) 입력란은 스펙에 없으므로 만들지 않는다 |
| 저장값 | `actual_weight = null` |
| 반복 | `target_reps_low~high` 범위 + `recommended_reps` 프리필 |
| RIR | 정상적으로 묻는다(엔진은 부하 판정에 쓰지 않지만 `too_hard` 판정에는 쓴다) |
| 레이아웃 | 무게 칸이 사라진 만큼 반복 입력칸을 넓힌다. 빈 칸을 남기지 않는다 |
| 볼륨 표기 | §10 C-6 `[확인 필요]` — 자체중량 세트의 볼륨 산입 규칙 미정. 확정 전까지 요약 화면에서 별도 문구를 만들지 않는다 |

- **AC-E-3** 자체중량 세트에는 무게 입력칸이 DOM에 없다.

### 5.4 시간 종목 — `metric: "time"`

> 대상 예: 플랭크. 무게·반복 대신 **목표 유지 시간(초)** 으로 처방·기록한다. **RIR을 묻지 않는다**(엔진이 적용하지 않으며 수집도 생략).

| 요소 | 규칙 |
|---|---|
| 무게 | 표시·입력 모두 없음 |
| 반복 | 표시·입력 모두 없음 |
| 목표 | `target_time_low_sec ~ target_time_high_sec` → "목표 40~60초". 두 값이 같으면 "목표 40초" |
| 입력 | **시간(초) 입력 1칸**. `inputmode="numeric"`, 단위 접미사 `초` |
| 프리필 | `target_time_low_sec`를 프리필한다 `[해석]`(하단 = 최소 성공 기준) |
| RIR | **묻지 않는다.** RIR UI를 렌더하지 않는다(비활성이 아니라 미렌더) |
| 저장값 | `actual_time_sec`. `actual_weight`/`actual_reps`는 `null` |
| 휴식 타이머 | 동일하게 동작(§4) |

- **AC-E-4** `metric = time` 세트에 RIR 입력이 DOM에 없다.
- **AC-E-5** `metric = time` 세트의 완료 체크는 시간 값만으로 가능하다.

### 5.5 추천 근거(`reason_code`) → 사용자 문구

`PlannedSet`에는 `reason_code`만 있고 자유 텍스트 설명이 없다(`Recommendation.explanation`은 요약 화면 전용). 루틴 화면의 근거 배지는 아래 **클라이언트 매핑**을 쓴다.

| `reason_code` | 화면 문구 |
|---|---|
| `BASELINE` | 첫 세션이라 무게를 직접 정해요 |
| `SIMILAR_INIT` | 비슷한 운동 기록으로 잡은 시작 무게예요 |
| `WEIGHT_UP_REP_TARGET_MET` | 지난번 목표 반복을 모두 채워서 무게를 올렸어요 |
| `ADD_ONE_REP` | 무게는 그대로, 반복을 1회 늘려요 |
| `HOLD_RIR_LOW` | 지난번이 힘들어 보여 무게를 유지해요 |
| `TOO_HARD` | 지난번이 버거워서 무게를 조금 낮췄어요 |
| `RIR_TOO_EASY_INCREASE` | 여유가 있어 보여 무게를 올렸어요 |
| `RIR_ON_TARGET_HOLD` | 강도가 목표에 잘 맞아요 |
| `RIR_TOO_HARD_REDUCE` | 강도가 높아 보여 부담을 줄였어요 |
| `REPS_UP_BODYWEIGHT` | 자체중량이라 반복 목표를 늘려요 |
| `PROGRESSION_CAP_BODYWEIGHT` | 반복이 충분히 늘어서 난도를 올릴 때예요 |
| `SUBSTITUTE_TOO_HARD_BODYWEIGHT` | 지금은 조금 버거워요. 보조 운동으로 바꿔 보세요 → [교체](F5 교체 팝업) |
| `TIME_UP` | 목표 시간을 채워서 조금 더 늘려요 |
| `TIME_HOLD` | 이번엔 같은 시간으로 유지해요 |
| `TIME_DOWN` | 목표 시간을 조금 낮췄어요 |
| `SUBSTITUTE_PAIN` | 통증이 기록돼서 다른 운동을 권해요 (+ 의료 조언 아님 고지) |
| `VOLUME_SPIKE_CAP` | 갑작스러운 운동량 증가를 막기 위해 조절했어요 |
| `DELOAD_SUGGESTED` | 회복을 위해 이번 주는 가볍게 가요 |
| `CALIBRATION_NEEDED` / `CALIBRATION_STALE` | 강도 감각을 맞추면 추천이 더 정확해져요 |
| `CALIBRATION_GRADUATED` | 강도 감각 측정이 끝나 추천에 반영했어요 |
| `INVALID_INPUT` | (표시하지 않는다 — 근거 영역 숨김) |
| 목록 밖 값 | **근거 영역을 숨긴다.** 코드 원문 노출 금지 |

- **AC-E-6** 알 수 없는 `reason_code`가 와도 화면에 영문 코드가 노출되지 않는다.

### 6.5 수용 기준

- **AC-P-1** 화면에 자유 텍스트 입력 요소가 0개다.

## 7. 접근성 체크리스트

기준: **WCAG 2.2 AA**. 아래는 AFC 화면에 대한 구체 적용이다.

### 7.1 포커스

| 항목 | 규칙 |
|---|---|
| 포커스 표시 | 모든 인터랙티브 요소에 보이는 포커스 링(두께 2px 이상, 인접 색 대비 3:1 이상). `outline: none` 단독 사용 금지 |
| 탭 순서 | DOM 순서 = 시각 순서. `tabindex > 0` 금지 |
| S4 탭 순서 | 운동 카드 → 세트 행 순서대로 → (무게 → 횟수 → RIR → 완료 체크) → 다음 세트 → 다음 운동 → [운동 종료] |
| 완료 체크 후 | 포커스를 타이머 팝업으로 이동(§7.2) |
| 팝업 닫힘 후 | 포커스를 **다음 미완료 세트의 첫 입력칸**으로 이동. 다음 세트가 없으면 트리거였던 완료 체크 버튼으로 복귀 |
| 스킵 링크 | 페이지 첫 포커스로 "본문 바로가기" 제공 |

### 7.2 모달·시트 포커스 트랩

대상: 휴식 타이머 팝업(F2), 운동 추가/교체 팝업(F5), 운동 종료 확인 시트(F6), 통증 안내 시트.

| 항목 | 규칙 |
|---|---|
| 역할 | `role="dialog"` + `aria-modal="true"` + `aria-labelledby`(제목 id) |
| 초기 포커스 | 타이머 = [휴식 종료], 추가/교체 = 부위 탭 첫 항목, 확인 시트 = **[취소]** |
| 트랩 | Tab/Shift+Tab이 다이얼로그 밖으로 나가지 않는다. 배경 콘텐츠는 `inert`(또는 `aria-hidden="true"`) |
| 닫기 | `Esc`로 닫힌다(타이머는 [휴식 종료]와 동일 동작, §4.6) |
| 복귀 | 닫힌 뒤 포커스는 §7.1 규칙대로 이동 |
| 스크롤 | 배경 스크롤 잠금 |

### 7.3 스크린리더 라벨

| 요소 | 마크업 |
|---|---|
| 세트 완료 체크 | `<button aria-pressed="false" aria-label="벤치프레스 2세트 완료 처리">`. 완료 시 `aria-pressed="true"`, 라벨은 "…완료 취소"로 교체 |
| 세트 행 상태 | 완료 표시는 아이콘+텍스트("완료"). 아이콘 단독일 경우 `aria-label="완료됨"` |
| 무게 입력 | `<input aria-label="벤치프레스 2세트 무게, 킬로그램" inputmode="decimal">` |
| 횟수 입력 | `aria-label="벤치프레스 2세트 횟수, 회"` `inputmode="numeric"` |
| 시간 입력 | `aria-label="플랭크 1세트 유지 시간, 초"` `inputmode="numeric"` |
| RIR 입력 | 그룹 `role="radiogroup" aria-label="남은 반복 수(RIR)"`, 각 옵션 `aria-label="RIR {n}"` |
| 무게 미정 배지 | `aria-label="추천 무게 없음, 직접 입력"` |
| 자체중량 배지 | `aria-label="자체중량 운동, 무게 입력 없음"` |
| 타이머 팝업 | `role="dialog" aria-label="휴식 타이머"` |
| 카운트다운 숫자 | `role="timer" aria-atomic="true"`. **`aria-live`는 `off`** (매초 낭독 금지) |
| 진행 바 | `aria-hidden="true"`(카운트다운과 중복 정보). 단독 사용 시에만 `role="progressbar" aria-valuemin/max/now` + `aria-valuetext="1분 30초 남음"` |
| +시간 버튼 | `aria-label="휴식 30초 추가"`. 상한 도달 시 `aria-disabled="true"`(DOM에서 제거하거나 `disabled`로 포커스를 뺏지 않는다) |
| 오프라인 배지 | `role="status"`, 텍스트 "오프라인" |

### 7.4 `aria-live` 사용처

| 위치 | 설정 | 낭독 내용 |
|---|---|---|
| 타이머 마일스톤 | 시각적으로 숨긴 `aria-live="polite"` 영역 | 남은 시간 60초·30초·10초·0초 시점에만 "1분 남음" / "30초 남음" / "10초 남음" / "휴식 완료". **매초 낭독 금지** |
| 시간 가산 결과 | 같은 polite 영역(500ms 디바운스 — 연타 시 마지막 값만) | "남은 시간 2분 30초" |
| 상한 도달 | 같은 polite 영역 | "휴식은 최대 10분까지 늘릴 수 있어요" |
| 세트 완료 토스트 | `role="status"`(= polite) | "2세트 완료" |
| 저장·동기화 상태 | `role="status"` | "저장했어요" / "오프라인, 기록은 저장됐어요" |
| 오류 배너 | `role="alert"`(= assertive) | 오류 문구 그대로 |
| 목록 갱신(F5 추가/삭제) | `role="status"` | "{운동 이름}을 루틴에 추가했어요" / "루틴에서 뺐어요" |

> assertive는 **오류에만** 쓴다. 그 외 전부 polite.

### 7.5 키보드만으로 핵심 루프 완주

다음 경로가 마우스·터치 없이 완주 가능해야 한다.

```
대시보드 [운동 시작] → 세트1 무게 입력 → Tab → 횟수 입력 → Tab → RIR 선택(←/→) →
Tab → 완료 체크(Enter/Space) → 타이머 팝업 자동 포커스 → (Tab으로 +30초) →
Enter로 [휴식 종료] → 다음 세트 입력칸에 포커스 → … → [운동 종료] → 확인 시트 → 종료
```

| 항목 | 규칙 |
|---|---|
| RIR 라디오 그룹 | 방향키로 이동, Space/Enter로 선택 |
| 세트 스테퍼 | ↑/↓로 증감 |
| 부위 탭(F5) | ←/→로 탭 이동(`role="tablist"` 표준 패턴) |
| 통증 부위 칩(F0) | Tab으로 순회, Space로 토글(`role="checkbox"` 또는 `aria-pressed` 버튼) |
| 모든 커스텀 컨트롤 | `div` + `onClick` 금지. 네이티브 요소 우선 |

- **AC-A-1** 위 경로를 키보드만으로 완주할 수 있다(마우스 이벤트 0회).
- **AC-A-2** 포커스가 보이지 않는 구간이 0개다.
- **AC-A-3** 타이머가 매초 낭독되지 않고, 마일스톤 4회만 낭독된다.

### 7.6 대비·타깃·색

| 항목 | 기준 |
|---|---|
| 본문 텍스트 대비 | 4.5:1 이상 |
| 큰 텍스트(18.66px bold / 24px 이상) | 3:1 이상 |
| UI 컴포넌트 경계·아이콘·진행 바 | 3:1 이상 |
| 비활성(disabled) 요소 | 대비 예외지만, **AFC에서는 3:1 이상 유지**(로깅 화면에서 상한 도달 버튼 등 상태 판독이 필요) |
| 터치 타깃 | 최소 44×44 CSS px. 인접 타깃 간 간격 8px 이상 |
| 완료 체크 버튼 | 한손 조작 대상이므로 최소 48×48 px |
| 색만으로 의미 전달 금지 | 완료 = 색 + 체크 아이콘 + "완료" 텍스트 / 오류 = 색 + 아이콘 + 문구 / 통증 경고 = 색 + 아이콘 + 문구 / 진행 바 = 색 + 숫자 카운트다운 |
| 모션 | `prefers-reduced-motion: reduce`에서 진행 바 transition·강조 애니메이션 제거 |
| 확대 | 200% 확대에서 가로 스크롤 없이 세트 행이 읽힌다 |
| 다크 모드 | 로깅 화면은 다크 고정(§8). 대비 기준은 동일하게 적용 |

## 8. 한 손 조작 원칙

전제: 세로 모드 한 손 파지, 기준 화면 폭 360~430px. 화면을 세로 3구역으로 나눈다.

| 구역 | 범위(세로) | 용도 |
|---|---|---|
| **상단** | 0~30% | 읽기 전용 정보(운동 이름, 목표, 근거 배지, 오프라인 배지). 액션 배치 금지(단, 뒤로가기 제외) |
| **중단** | 30~65% | 값 입력(무게·횟수·RIR). 스크롤 영역 |
| **하단(엄지 반경)** | 65~100% | **주 액션**: 세트 완료 체크, 타이머 [휴식 종료]/[다음 세트], +시간 버튼, 확인 시트 버튼 |

| 규칙 | 내용 |
|---|---|
| 세트 완료 체크 위치 | 세트 행의 **오른쪽 끝**(엄지 자연 궤적). 행 높이 56px 이상 |
| 타이머 팝업 | 화면 **하단에서 올라오는 시트**로 띄운다. 큰 카운트다운은 시트 상단, 조작 버튼은 시트 하단 |
| +시간 버튼 4개 | 한 줄 4등분, 각 44px 이상. [휴식 종료] 바로 위 |
| [휴식 종료] | 시트 최하단 전폭 |
| [운동 종료] | 루틴 목록 **최하단**(F6 명세 그대로). 스크롤 없이 도달할 수 없어도 위치를 바꾸지 않는다 — §10 C-7 `[확인 필요]`(고정 바 도입 여부) |
| 파괴적 액션 | [삭제]는 운동 카드의 오버플로 메뉴 안에 두고, 엄지 반경 주 영역에 노출하지 않는다(오조작 방지) |
| 좌우 대칭 | 왼손 사용자를 위해 주 액션은 화면 **하단 전폭** 또는 중앙 정렬을 우선한다. 오른쪽 구석 전용 배치 금지(FAB 미사용) |
| 로깅 화면 테마 | **다크 고정**(헬스장 조명·눈부심·배터리). 대비는 §7.6 유지. 실값은 design 토큰과 협의 |
| 입력 키패드 | 숫자 입력에 `inputmode` 지정으로 숫자 키패드가 바로 뜨게 한다(무게 `decimal`, 횟수·시간 `numeric`) |
| 스크롤 | 타이머 시트가 떠 있는 동안 배경 스크롤 잠금(오조작으로 값이 어긋나지 않게) |

- **AC-H-1** 세트 완료 체크·[휴식 종료]·+시간 버튼이 모두 화면 하단 35% 안에 있다.
- **AC-H-2** 로깅 화면의 모든 주 액션 타깃이 44px 이상이다.
- **AC-H-3** 로깅 화면에서 [삭제]가 한 번의 탭으로 실행되지 않는다.

## 10. 확인 필요 목록 (임의 결정 금지)

| # | 항목 | 왜 막혔나 | 필요한 결정 |
|---|---|---|---|
| **C-1** | **오늘 세션 진입 경로** | `GET /sessions/{id}`는 id가 필요한데, `DashboardSummary`·`Program` 어디에도 `session_id`가 없다. 오늘의 세션 id를 얻을 계약 경로가 없다 | `DashboardSummary.today`에 `session_id` 추가 / `GET /sessions?date=` 추가 / 그 밖 방식 중 택1 (tech-lead + backend) |
| **C-2** | 세션 응답에 운동 표시명이 없다 | `PlannedSet`은 `exercise_id`만 준다. `GET /exercises`가 501이라 STEP 5 시작 시 이름조차 못 그린다 | `GET /exercises` 구현 순서를 STEP 5 최우선으로 확정(PROGRESS 이월 항목과 동일) |
| **C-3** | 409 원인 구분 불가 | 세 원인(완료된 세션·중복 종목·수행 기록)이 모두 `code: "CONFLICT"`. 한국어 메시지 매칭은 취약 | `error.details.reason` enum 추가 여부 |
| **C-4** | 오프라인에서 루틴 편집(F5) 허용 여부 | FEATURES_UX는 "세트 완료·루틴 편집·운동 종료 모두 로컬 우선 저장 후 /sync"라고 하지만, `/sync`의 `Mutation.entity`는 `performed_set|session|profile`뿐이라 **운동 추가/삭제/교체를 실을 자리가 없다** | 편집을 온라인 전용으로 둘지, `/sync` 계약을 넓힐지 (STEP 6 설계와 직결) |
| **C-5** | 운동 종료 시 피드백(`difficulty`/`pump`/`pain`) 수집 여부 | openapi `complete` 바디에는 있으나 F6에는 입력 단계가 없다 | 수집한다면 어느 화면·필수 여부 |
| **C-6** | 자체중량·시간 종목의 볼륨 산입 | 요약·대시보드의 `total_volume` 정의가 스펙에 없다. 무게 null을 0으로 곱하면 볼륨이 0이 된다 | 산입 규칙 + 화면 표기 문구 |
| **C-7** | [운동 종료] 버튼 위치 | F6은 "최하단". 한 손 원칙(§8)은 하단 고정 바를 선호. 긴 루틴에서는 스크롤이 필요 | 최하단 유지 / 하단 고정 바 병행 중 택1 |
| **C-8** | 완료 체크 해제 시 수행 기록 처리 | 서버는 `performed_sets` **행 존재**만으로 삭제·교체를 409로 막는다(`completed` 값을 보지 않는다). 체크를 해제해도 행이 남으면 E-14 문구("완료 체크를 먼저 해제해 주세요")가 거짓말이 된다 | 해제 = 행 삭제 / 서버 조건을 `completed = true`로 한정 중 택1 (STEP 6) |
| **C-9** | 시간 목표 범위가 붕괴하는 경우 | `TIME_DOWN`이 상·하단에 독립 적용돼 `10~10초`처럼 폭이 0이 될 수 있다(PROGRESS 열린 질문) | 화면에 "목표 10초"로 표기해도 되는지, 규칙을 고칠지 |
| **C-10** | 다크 모드 범위 | 로깅 화면 다크 고정은 정했으나 대시보드·온보딩의 테마 정책은 미정 | 전역 다크 / 로깅만 다크 (design 협의) |

> 위 항목은 **frontend가 구현으로 결정하지 않는다.** 결정 전에는 해당 UI를 만들지 말고 §2의 대체 상태(빈/비활성 + 안내 문구)로 처리한다.
