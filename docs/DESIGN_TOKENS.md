# 디자인 토큰 (UI/UX 확정안 v2, 2026-08-09)

> **출처**: 제품 오너가 확정한 프로토타입 7종(홈 대시보드 / 온보딩 / 세션 / 기록 / 주간 프로그램 / 페이월 B / RIR 캘리브레이션).
> 값은 **프로토타입 HTML 에서 실측 추출**했다(추정·보간 없음). 빈도는 7개 파일 합산 출현 횟수다.
>
> **상태**: 토큰 정의는 확정. **단 §3 의 대비 미달 4건은 그대로 구현하면 axe 게이트가 깨진다** — 보정 승인 전에는 구현하지 않는다.
> 적용은 마일스톤 **M-UI** 범위. 계약(openapi)·추천 엔진·골든과 무관하다.

### 2.3 의미 규칙 — 색으로 말하는 것

- **파랑은 "지금·추천·계획과 다름"**. 성공이 아니다. 감량 추천(▼)도 파랑이다 — 나쁜 일이 아니기 때문.
- **초록은 완료와 증량**에만. 세트 체크 배경, ▲델타, PR.
- **노랑은 범위 밖**, **빨강은 한계**(RIR 0 · 통증 7+). 둘 다 차단이 아니라 표시다.
- 색만으로 상태를 전하지 않는다 — 완료는 `✓`, 부분은 `½`, 오늘은 `●`, 델타는 `▲/▼` 를 함께 쓴다.

## 3. ⚠ 대비 미달 — 구현 전에 반드시 처리

WCAG 2.1 AA 로 전 조합을 계산했다(계산기 자가검증: 흑백 21.00, `#767676` on 흰 4.54 — 기준값과 일치).

### 3.1 텍스트 4.5:1 미달 4건 — **axe 게이트가 깨진다**

| 조합 | 실측 | 최소 보정안 | 보정 후 |
| --- | --- | --- | --- |
| `success #1B8A4B` on 흰 | **4.39:1** | `#198146` | 4.92:1 |
| `success` on `success-bg #EFF8F2` | **4.05:1** | `#198146` | 4.54:1 |
| `warn #D08A00` on 흰 (볼륨 초과 숫자) | **2.87:1** | `#9A6600` | 4.91:1 |
| 흰 글자 on `warn` 배경 (통증 4–6 칩) | **2.87:1** | `#A16B00` | 4.55:1 |

- `success` 는 **`#198146` 하나로 두 조합을 동시에 통과**한다. 눈으로는 거의 구분되지 않는다.
- `warn` 은 프로토타입이 이미 `warn-ink #8A6100`(흰 위 5.54:1)을 갖고 있다.
  **텍스트에는 `warn-ink`, 면(배지 배경·바 채움)에는 `warn #D08A00`** 으로 역할을 갈라 쓰면 새 색 없이 해결된다.
- 이 프로젝트는 **완료 행 대비가 4.01:1 이라 실패한 전례**가 있다(ADR-41). 같은 급의 문제다.

### 3.1.1 보정 후 전수 재계산 (2026-08-09, M-UIa 착수 전)

D-1 승인 보정(`success #198146`, warn 텍스트는 `warn-ink #8A6100`)을 넣고 **실제로 함께 쓰이는 21개 조합**을
다시 계산했다(계산기 자가검증: 흑백 21.00 / `#767676` 4.54). 안 쓰는 조합의 미달은 판정에서 제외한다.

**20/21 통과. 남은 미달 1건:**

| 조합 | 실측 | 용례 |
| --- | --- | --- |
| 흰 글자 on `warn` 면 `#D08A00` | **2.87:1** | 통증 4~6 강도 칩(선택 상태) |

보정 후보 두 가지 — **D-4 로 올린다**:
- (a) 선택 칩의 면을 `#A16B00` 으로 어둡게(흰 글자 4.55:1). 새 색 1개 추가.
- (b) 선택 칩을 **면 `warn-bg #FCF6E7` + 글자 `warn-ink #8A6100`** 으로(5.14:1). **새 색이 필요 없다.**
  다만 "선택됨"의 시각적 강도가 다른 칩(ink 반전)과 달라진다.

> **여유가 거의 없는 조합**: `success #198146` on `success-bg #EFF8F2` = **4.54:1**(기준 4.5).
> 배경을 조금만 밝기 조정해도 깨진다. `success-bg` 는 **건드리지 말 것**.

### 3.2 비텍스트 3:1(WCAG 1.4.11) — 판단 필요

`border #C9D0DA` 는 흰 위 **1.55:1**. 장식 구분선은 면제지만, **입력칸 경계는 UI 컴포넌트**라 3:1 이 필요하다.
세트 행의 대기(pre) 상태 입력칸은 배경도 `bg #F5F7FA`(흰 대비 1.06:1)라 **경계가 테두리에만 의존**한다.

- axe 기본 룰셋은 1.4.11 을 검사하지 않는다 → **게이트는 통과하지만 접근성 구멍은 남는다.**
- 최소 보정은 `#8A8E95`(3.29:1)지만 얇은 실선의 인상이 바뀐다.
- **팔레트 안에서 해결하는 안**: 구분선은 `border` 유지, **인터랙티브 컨트롤 경계에만 `muted #5D6875`(5.67:1)** 를 쓴다. 새 색이 없다.
- → **D-7 로 올린다.**

## 4. 타이포

```
본문  Pretendard, -apple-system, 'Noto Sans KR', sans-serif
숫자  'JetBrains Mono', monospace  +  font-variant-numeric: tabular-nums
```

**모노를 쓰는 곳**: 무게·횟수·RIR·시간·퍼센트·세트 카운트·`reason_code`·uppercase 키커 라벨.
자릿수가 바뀌어도 열이 흔들리면 안 되는 곳 전부. `tabular-nums` 는 선택이 아니라 필수다.

| 역할 | 크기 | 비고 |
| --- | --- | --- |
| 키커(uppercase 라벨) | 9.5px | `letter-spacing:.14em`, `muted`, 모노 — 최다 빈도(139) |
| 섹션 키커(상단) | 10–11px | `.18em` |
| 캡션·메타 | 11–12px | |
| 본문 | 12.5–13.5px | `line-height:1.55~1.6` |
| 강조 본문·버튼 | 14.5–15px | `letter-spacing:-.01em` |
| 소제목 | 16–20px | `-.02em` |
| 지표 수치 | 22–32px | 모노, `-.03em` |

> 9.5px 는 **모노 대문자 라벨 전용**이다. 한글 본문에 쓰면 안 된다.
> 현재 토큰의 `--text-metric: 2rem`(32px)·`--text-timer: 3.75rem`(60px)와 충돌한다 — 타이머 크기는 프로토타입에 없어 **미해결**(§7).

## 5. 형태

| 항목 | 값 |
| --- | --- |
| radius | `1px`(게이지 칸·바) / `2px`(칩·버튼·입력·작은 컨트롤, 136회) / `3px`(카드·시트·주요 버튼, 188회) |
| 테두리 | `1px` 기본 / `1.5px` 강조 카드·보조 버튼 / `1.4px` 게이지 칸 / `1.6px` 체크·라디오·상태 마크 / `1.8px` 라디오(온보딩) |

| 포커스 | `outline: 2px solid #1B4FC4; outline-offset: 2px` (`:focus-visible`) |

`radius 12/14px` 는 목업 프레임 값이므로 **토큰이 아니다**.

현재 `apps/web/app/globals.css` 는 **의미 기반 토큰**이라 이름은 대부분 살아남고 **값만 교체**된다. 이게 M-UI 를 작게 만든다.

Pretendard 도 동일. → M-UI 작업 항목.

## 8. 미해결

1. **다크 모드**(ADR-30 폐기 여부) — 프로토타입에 다크가 없다. **D-6.**
2. **휴식 타이머 카운트다운 크기** — 프로토타입 시트에 대응 값이 없다(현재 60px). M-UI 에서 실측 재산출.
3. **`border` 3:1 문제** — §3.2, **D-7.**
4. 애니메이션 토큰 없음. `prefers-reduced-motion` 처리만 프로토타입에 있다(현재 구현과 동일).
