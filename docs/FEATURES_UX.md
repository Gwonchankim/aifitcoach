# AFC 핵심 기능·UX 명세

> 대상: STEP 5(프론트 핵심 플로우)와 관련 백엔드(STEP 1/2/4). 이 문서의 동작을 그대로 구현한다.
> 브랜드: AIFITCOACH(줄여서 AFC). 화면 표기는 "AFC" 또는 "AIFITCOACH".

## 용어
- **데일리 루틴(Daily Routine)** = 오늘의 세션(workout_session). 기본은 AI 추천 루틴, 사용자가 편집 가능.
- **세트(Set)** = planned_set 1개(운동 × set_no). 완료 시 performed_set로 기록.

## F0. 온보딩 (프로필·목표·문진)
- 수집: 프로필(성별·출생연도·키·체중), 목표(다이어트/근비대/스트렝스), 주당 일수, 1회 운동 시간, **운동 경력**(초급/중급/고급), 보유 장비, 통증 부위(`pain_areas`).
  - **운동 경력(`experience_level`)은 `POST /programs/generate`의 필수 필드**이고 세트 수·목표 RIR에 영향을 준다. 기본값으로 고정하면 고급자가 초급 프로그램을 받는다.
  - 프로필(성별·출생연도·키·체중)은 현재 계약에 전송할 자리가 없다(`PATCH /me`는 테스트 단계 보류) → 로컬에만 보관하고, 인증 도입 시 서버로 옮긴다.
- 완료 시 `POST /v1/programs/generate` → 생성된 프로그램의 '왜 이 루틴' 근거와 **제외된 운동·사유**(`Program.excluded_exercises`)를 보여준다.

### F0-0. 스텝 버튼 배치 (확정 2026-08-05)
> 7스텝을 연속으로 누르는 화면이라 버튼 위치의 마찰이 누적된다. 특히 주당일수·시간 스텝은 칩 한 줄이라
> 콘텐츠가 화면 상단 1/4만 차지하는데 버튼이 화면 최하단에 고정되면 가운데가 통째로 비고 엄지를 과하게 내려야 한다.

- **"짧으면 따라 올라오고, 길면 고정"**: 콘텐츠가 짧아 스크롤이 없는 스텝은 버튼이 **콘텐츠 흐름을 따라** 올라오고, 콘텐츠가 길어 스크롤이 생기는 스텝은 **하단 고정(sticky)** 으로 동작한다.
- 버튼은 한 손 조작 기준 **엄지 범위(화면 하단 1/3)** 에 들어오되 **화면 맨 끝에 붙지 않게** 하단 여백을 확보한다. 모바일 **safe-area(홈 인디케이터)** 를 고려한다.
- 하단 여백 하한은 **24px**로 유지한다(safe-area가 더 크면 그 값을 따른다).
- 터치 타깃 최소 44px과 큰 탭 원칙은 그대로이며, 테마는 라이트 전용(ADR-30 폐기 유지)이다.

### F0-1. 통증 부위 입력 (안전 — 자유 입력 금지)
> `pain_areas`는 **안전 필드**다. 서버가 enum 8종만 받고 그 외는 400으로 거부한다(조용한 무시 없음).
> 따라서 UI가 잘못된 값을 만들 수 없어야 한다.

- **자유 텍스트 입력을 제공하지 않는다.** 8개 부위를 **체크박스/칩 형태의 다중 선택**으로만 제공한다.
- 라벨은 한국어, 전송값은 enum:

| 표시 라벨 | 전송값 |
|---|---|
| 무릎 | `knee` |
| 허리 | `lower_back` |
| 어깨 | `shoulder` |
| 팔꿈치 | `elbow` |
| 손목 | `wrist` |
| 고관절 | `hip` |
| 목 | `neck` |
| 발목 | `ankle` |

- **"해당 없음"** 선택지를 포함한다. 선택 시 `pain_areas`는 **빈 배열**로 전송한다(다른 부위와 동시 선택 불가).
- 목록에 **없는 부위는 선택할 수 없음**을 안내하고, **심한 통증은 전문가 상담 안내**로 연결한다.
- 이 목록은 `docs/SAFETY_PAIN_MAPPING.md`의 제외 매핑과 **1:1로 정합**해야 한다(부위가 늘거나 줄면 문서·openapi enum·UI를 함께 바꾼다).
- 안내 문구에 "일반적 회피 가이드이며 의료적 조언이 아님"을 명시한다.

## F1. 세트 기록 & 완료 체크
- 각 세트 UI: 무게(kg) 입력, 횟수(reps) 입력, (선택) **RIR 입력**, **완료 체크 버튼**.

### F1-0. 세트 행 레이아웃 (확정 2026-08-05)
> 세트 1개가 4줄(무게·횟수 / RIR / 배지 / 목표·직전)로 흩어지면 운동 중에 한눈에 안 들어온다.

- **세트 1개 = 가능하면 한 줄, 최대 두 줄.**
  - **주(primary)**: 무게 · 횟수 · RIR · 완료 체크 버튼.
  - **보조(secondary)**: 목표 · 직전 기록 · 배지는 **작게**.
- **중복 제거**: "무게 미정" 배지를 세트마다 반복하지 않는다(운동 카드 상단에 같은 안내가 이미 있다).
- **직전 기록**은 별도 줄을 만들지 말고 입력칸 placeholder 또는 한 줄 보조 텍스트로 압축한다.
- **완료된 세트는 1줄로 축약**해 보여준다. 단 F6-1(당일 수정)이 있으므로 **편집 진입이 어렵지 않아야** 한다.
- 밀도 회귀 가드를 유지한다(세트당 높이 상한). 재설계 시 상한을 새 기준으로 다시 잡되 **총 높이가 줄어야** 한다.

### F1-1. RIR 입력 (확정 2026-08-05, 2차 개정)
- **하나의 필드**로 제공한다 — 숫자를 직접 칠 수도 있고 목록에서 고를 수도 있는 **단일 입력**(입력칸 + 별도 드롭다운 2개로 나누지 않는다).
- 범위 **0~6** — `docs/RECOMMENDATION_ENGINE.md`의 `corrected_RIR = clamp(reported + rir_bias, 0, 6)`과 일치시킨다.
- **미입력(모름)을 허용한다.** 미입력이면 엔진이 **RIR 축 판정을 보류**하고 반복 기반 더블 프로그레션으로 간다(기존 동작 유지). 미입력을 0으로 바꿔 보내지 않는다.
- 모바일에서 조작이 쉬워야 한다(직접 타이핑과 선택 둘 다 한 손으로 가능).
- **목표 RIR**(예: `target_rir = 2`)을 **같은 세트 행 안에서 함께** 보여 사용자가 기준을 알 수 있게 하고, 입력칸과 접근성으로 연결한다.
  - 구현(2026-08-06 확정): 1줄차에 넣을 폭이 없어 **2줄차 보조 텍스트("RIR 목표 2") + `aria-describedby` 연결**로 둔다. 근거는 `docs/UX_STATES.md` AC-RIR-4.
- 범위 밖 값은 UI가 애초에 만들 수 없어야 한다(입력 시 제한).
- 추천값(recommended_weight/reps)을 입력칸에 프리필하고, 이전 기록도 함께 보여준다.
- 완료 체크 클릭 = 그 세트를 **완료로 기록**(로컬 우선 저장 → outbox, STEP 6). 완료 세트는 체크 표시와 완료 전용 토큰으로 구분한다(행 전체 opacity 금지, ADR-41).
- 완료 체크 터치 타깃은 **48×48px**로 고정한다(D-16).
- 완료 체크는 되돌리기(uncheck) 가능해야 한다(오입력 대비).
- **Sprint 0 계약 잠금(D-13)**: 이 RIR 계약을 유지한다. 즉 **0~6 + 미입력(`null`)**, 숫자 직접 입력, 필드 안 셰브론으로 여는 바텀시트가 범위다. 프로토타입의 **0~5·기본값 2·길게 누르기·화면 ± 스테퍼·3초 undo**는 이번 범위에서 제외한다(기존 키보드 ↑/↓ 입력은 유지).

## F2. 휴식 타이머 팝업 (완료 체크 시 자동)
- 세트 완료 체크 → **추천 휴식시간 카운터 팝업**이 자동으로 뜬다. 추천값 = 해당 planned_set의 `rest_sec`(목표별 기본: 근비대 90~180, 스트렝스 180+, 다이어트 60~90).
- **초 단위 카운트다운**을 크게 표시. 카운터 **아래에 진행 바(스테이징 바)** 가 100%→0%로 점점 줄어들며 남은 시간을 시각화.
- 0초 도달 시: (옵션) 사운드/진동 알림 + 팝업 자동 닫힘(또는 "다음 세트" 준비 상태).

## F3. 휴식시간 증가 버튼 (+5초 / +10초 / +30초 / +1분)
- 팝업에 4개 버튼: **+5초, +10초, +30초, +1분**.
- 클릭/**연타** 시 그 값만큼 **현재 카운터에 즉시 가산**하고, 연타 횟수만큼 누적된다(예: +30초 3연타 = +90초). 진행 바도 새 총시간 기준으로 갱신.
- 합리적 상한(예: 10분)만 두고 그 안에서 자유 증가.

## F4. 휴식 종료 버튼
- 팝업 **하단에 "휴식 종료" 버튼**. 클릭 시 **즉시** 타이머 종료·팝업 닫고 다음 세트로 진행.

## F5. 데일리 루틴 커스터마이징 (추가 / 삭제 / 교체)
- 데일리 루틴은 기본 AI 추천이지만 사용자가 오늘 루틴을 편집할 수 있다(세션 스코프, 오늘만).
  - **운동 삭제**: 루틴에서 해당 운동 제거.
  - **운동 추가**: "운동 추가" → **팝업**에서 **부위별**(가슴·등·어깨·팔·하체·코어) 탭 + 종목 리스트(운동 DB)에서 선택해 추가.
  - **운동 교체**: 해당 운동의 "교체" → **팝업**에서 부위별 대체 종목 선택. 대체 후보는 **같은 movement_pattern 우선 정렬**(exercises.substitutions 활용).
- 추가/교체 팝업은 운동 DB(exercises)에서 부위(primary_muscles/region)로 필터링해 보여준다.
- 운동 카드의 `⋯` 트리거는 카드에 앵커된 **3항목 메뉴(교체 / 통증 기록 / 삭제)** 를 연다(D-14·D-17). **건너뛰기**는 이번 범위에 포함하지 않는다.
  - 메뉴는 `role="menu"` 패턴으로 방향키 이동, `Esc`, 외부 클릭 닫기, 닫힌 뒤 트리거 포커스 복귀를 지원한다.
  - **기록이 있는 운동은 교체·삭제 불가**다. 두 항목은 DOM과 탭 순서에 남는 `aria-disabled="true"` 항목으로 제공하고, 활성화 시 네트워크 요청을 **0회** 보내며 사유를 화면 표시와 `role="status"`로 낭독한다.
  - 같은 잠금 상태에서도 **통증 기록은 활성**으로 유지한다.
  - **[운동 추가]는 세트 목록 하단**에 둔다. 중간 [편집] 시트는 두지 않는다.
- 편집 결과는 오늘 세션의 planned 운동/세트에 반영된다(아래 API).

## F6. 운동 종료 버튼 → 기록 & 이후 추천 반영
- 데일리 루틴 **최하단에 "운동 종료" 버튼**. 이 버튼을 눌러야 개인 운동 내역이 **기록**된다(세션 완료).
- 운동 종료 = `POST /v1/sessions/{id}/complete` → 서버가 추천 엔진으로 **다음 세션의 추천(운동·무게·횟수)** 을 재계산(RECOMMENDATION_ENGINE.md). 이후 같은 부위/운동 수행 시 추천이 제안된다.
- 운동 종료 시 요약(볼륨·완료 세트·PR·다음 추천 미리보기)을 보여준다.

## F7. 부분 수행 허용
- 모든 운동/세트를 하지 않아도 "운동 종료"를 누를 수 있다.
- **완료 체크된 세트만** performed_set로 기록되고, 미수행 세트는 기록하지 않는다(추천은 수행 데이터만 사용).
- 세션은 부분 완료여도 completed로 처리된다.

## F6-1. 종료 후에도 당일 기록 추가·수정 (확정 2026-08-05)
> 실사용에서 운동을 끝낸 뒤 추가로 더 하거나, 잘못 입력한 값을 고치는 일이 흔하다.
> 종료했다고 그날 기록을 잠그면 사용자가 사실과 다른 기록을 남기게 된다.

- **당일에 한해** 종료된 세션을 다시 열어 **세트 추가·수정·루틴 편집**을 할 수 있다(재개/편집 모드).
- **다른 날짜의 종료된 세션은 읽기 전용**이다(과거 기록의 소급 변경 금지 → 이미 나간 추천의 근거가 바뀌지 않게 한다). 이 경우에만 충돌(409)로 막는다.
- 수정·추가가 발생하면 **추천 재계산이 다시 돈다**(운동 종료 시의 재계산 경로를 재사용). 재계산은 **멱등**이어야 한다 — 같은 입력으로 여러 번 돌려도 결과가 같아야 하고, 목표가 두 번 올라가면 안 된다.
- 대시보드·요약의 "오늘 기록"은 수정 결과를 반영한다.
- 오프라인(STEP 6)과의 정합: 수정도 세트 로깅과 같은 outbox 경로를 타고 `client_id` 멱등 + `updated_at` LWW로 해소한다. 종료 후 수정이 재전송돼도 중복 기록이 생기지 않아야 한다.

## F8. 대시보드
- 대시보드 화면에서 현재까지 수행 요약과 오늘/내일 상태를 보여준다.
- 오늘 상태는 미수행/진행 중/완료/부분 수행/휴식/계획 충돌/공백 후 복귀/프로그램 없음으로 표현한다.
  계획 충돌·공백 복귀는 표시 계층 상태이며 추천 감량이나 일정 변경을 자동 실행하지 않는다(D-41·D-42).
- 완료 요약의 총 볼륨·완료 세트·PR과 주요 리프트 e1RM은 같은 공용 e1RM 집계 공식을 사용한다.
- 이번 주 리듬, 계획 준수율, 연속 완료 운동일, 서버가 3세션 게이트를 적용한 주요 리프트 추세를 보여준다.
- 해당 종목의 완료 세션이 3회 미만이면 e1RM 수치·추천·추천 근거를 노출하지 않는다.

### F8-1. 휴식일에도 운동하기 (확정 2026-08-05)
- "오늘은 휴식"일 때도 **[그래도 운동하기]** 경로를 제공한다. 휴식일이라고 앱이 사용자를 막지 않는다.
- **루틴 결정 방식: 부위 선택 후 즉석 생성.** 가슴·등·어깨·팔·하체·코어 중 하나를 사용자가 고르면 그 부위 루틴을 새로 만든다(F5 추가 팝업의 부위 구분과 동일).
  - 근거: 사용자 통제가 가장 크고, "오늘 뭘 하고 싶은지"를 앱이 대신 정하지 않는다. 다음 예정 세션을 당겨오면 이후 일정 재배치 문제가 생긴다.
  - 대가: **주간 볼륨 캡 밖의 추가 볼륨**이 발생한다. 아래 안전 안내로 보완한다.
- 즉석 세션도 **프로그램에 속하고 `user_id`에 매달린다**. 추천 엔진은 평소와 동일하게 동작한다(수행 기록이 쌓이면 다음 추천에 반영).
- **안전(회복 안내)**: 연속 운동일이 과도해지면(**7일 연속 이상**) 회복을 권하는 안내를 노출한다. 막지는 않되, 휴식의 필요를 알린다. 문구는 단정적 의학 표현을 쓰지 않는다(`docs/SAFETY_PAIN_MAPPING.md`의 기조와 동일).
- 이미 오늘 세션이 있으면 즉석 생성 대신 그 세션으로 이동한다.

## F9. 기록

- 종목별 완료 세션 수, 이전 기록, e1RM 추이, PR 값·날짜·세션과 완료 세션 목록/상세를 보여준다.
- 0회는 기록 없음, 1~2회는 날짜 observation만 점으로 표시하고 선·e1RM 수치·다음 추천을 숨긴다.
  3회 이상부터 서버가 게이트한 e1RM points와 다음 추천을 표시한다.
- 세션 상세는 계획값과 실제 무게/반복/RIR/시간을 세트별로 대응해 보여준다.
- 사용자가 과거 날짜 기록을 새로 입력하는 backfill은 포함하지 않는다(ADR-38 유지, D-43).

## F10. 주간 프로그램

- 프로그램의 12주 중 현재 주차, 이번 주 날짜별 진행, 근육군별 hard sets와 목표별 권장 범위를 보여준다.
- 12주 전체 세션을 미리 만들지 않는다. 실제 생성된 세션과 template에서 합성한 미래 주차 `예정`을 구분한다.
- 근비대는 10~20, 다이어트는 8~14 hard sets를 기준으로 표시한다. 스트렝스는 승인된 범위가 없어
  실제값만 보여주고 범위 경고를 만들지 않는다.
- 범위 이탈·계획 충돌은 읽기 전용 안내다. 프로그램 일정 재배치 mutation은 만들지 않는다(ADR-24).

## 데이터·계약 영향 (STEP 1/2/4 반영)
- **세션 편집 엔드포인트**(오늘 루틴 add/remove/swap) — openapi.yaml에 추가됨:
  - `POST /v1/sessions/{sessionId}/exercises` (운동 추가)
  - `DELETE /v1/sessions/{sessionId}/exercises/{plannedExerciseId}` (삭제)
  - `POST /v1/sessions/{sessionId}/exercises/{plannedExerciseId}/swap` (교체)
- **대시보드 엔드포인트** — `GET /v1/dashboard` (DashboardSummary).
- **집계 엔드포인트** — `/analytics/e1rm|volume|completion`. 서버가 3세션 표시 게이트를 적용한다.
- **프로그램 lifecycle** — `started_at`, `total_weeks=12`, `status`; 세션은 lazy 생성한다.
- **휴식 타이머/증가/종료**는 순수 클라이언트 UI 상태(서버 저장 불필요). 추천 휴식값은 planned_set.rest_sec.
- **부분 수행**: performed_sets는 완료 체크된 세트만 생성. session complete가 부분이어도 허용.
- **오프라인**(STEP 6): 세트 완료·루틴 편집·운동 종료 모두 로컬 우선 저장 후 /sync로 동기화.

## 안전
- 휴식 타이머 사운드/진동은 옵션(기본 off 가능).
- 로깅 화면에 통증 보고(pain) 입력과 안전 플로우(pain_score≥4 → 대체/감량 안내)를 유지(RECOMMENDATION_ENGINE.md).
